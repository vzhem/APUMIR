# APU v11.74.122 — устройства одного аккаунта видят переписку сразу

## Что изменилось (раунд 226)

Владелец: «пишешь на телефоне — сразу везде; входящее приходит сразу и на
телефон, и на ПК; мгновенно, если оба в сети; кто долго был офлайн — сам
догоняет при появлении сети».

Два устройства одного аккаунта (например, телефон и Android на ПК после
«Синхронизировать аккаунт») теперь работают как одно целое:

- написали на одном — строка сразу видна на втором, без кнопок и ожиданий;
- входящее от собеседника приходит сразу на оба устройства, у каждого своё
  уведомление;
- кто был офлайн — догоняет пропущенное сам, как только появится сеть;
- сеть ведёт одно устройство (у аккаунта одна сессия), второе живёт его
  событиями и само подхватывает работу, если первое пропало.

Пока так идут тексты личных чатов. Картинки, файлы, гифки, стикеры,
группы и каналы — как раньше: переносятся полной копией аккаунта
(«Синхронизировать аккаунт»).

Включать нечего: устройства находят друг друга сами, если на обоих один
ник и профиль перенесён. Пока второе устройство ведёт не оно, оно
показывает «APU: сеть ведёт другое устройство (зеркало)».

## Владельцу: перед обновлением телефонов

1. **Обновить воркер** (без него синхронизации нет): dashboard →
   Workers & Pages → p2p-relay → Edit code → вставить весь
   `tools/worker/p2p_relay_worker.js` из репозитория → Deploy. Тот же
   деплой приносит маршрут `/mirror` и кэш `/update/latest` (когда GitHub
   отвечает 403, телефоны получают последний удачный ответ, а не пустоту),
   а вместе с `/psync` закрывает долг за v11.74.121.
2. **Поставить воркфлоу**: `powershell -NoProfile -ExecutionPolicy Bypass
   -File .\scripts\install-release-workflow.ps1` — шаг K6 (тесты ядра перед
   сборкой) и догон `main`.
3. **Проверить по чек-листу** `docs/MIRROR_SYNC.md` §7 (роли, мгновенное
   исходящее/входящее в обе стороны, догон, подхват). На телефонах это
   ещё НЕ проверялось.

SUCCESS, APK 40 736 374 Б, `sha256 b2c81d7c…f229`; релиз собран

## Как это устроено (коротко)

- У аккаунта одна сессия, поэтому сеть ведёт ОДНО устройство (кто раньше
  стартовал ядро; при равенстве — меньший тег). Второе — зеркало: движок
  не запускает, живёт событиями через лёгкий WebSocket-канал к воркеру.
- Канал: комната на воркере по полке, выведенной из nodeId
  (`sha256("apu-mirror-v1|" + nodeId)`); вводить адреса не нужно.
- Содержимое кадров запечатано на самого себя (тот же файловый конверт,
  что в обмене файлами): воркер видит только маршруты.
- Пропуски закрывает догон: устройства обмениваются свежестью базы,
  отставшее само просит хвост порциями.
- Смена роли — штатный перезапуск сервиса (~1.5 с и подъём движка).

Подробности, карта кода и ограничения — `docs/MIRROR_SYNC.md`.
