# APU v11.74.104 — вход по никнейму: «полка пуста» ≠ «сервер недоступен»

## Что изменилось (раунд 207)

Владелец (скрин онбординга на ПК/WSA, вкладка «Я уже зарегистрирован»,
@server21): «Хотел установить приложение на ПК через лаунчер и войти
под своим же именем. Но не получается» - «Под этим никнеймом ничего не
сохранено. Проверьте написание.»

### Диагностика (напрямую)

- Воркер p2p-relay здоров ({"status":"ok"}; утром был Cloudflare 1027 -
  лимит Free-плана, к вечеру отпустило).
- Полка @server21 НЕ ПУСТА: shelf = sha256("apu-identity-vault-v1:shelf:server21")
  → GET /vault/get?shelf=… возвращает зашифрованный сундук. Данные целы.
- Пустая полка отвечает {"error":"not found"} - сервер честен.

### Причина

BotApi.fetchIdentityVault возвращал null и на «полка пуста»
(error-json), и на любой сбой сети (не-200, таймаут, 1027-HTML), а
IdentityBackup.restore трактовал null как NotFound. Владельцу при
сбоете сети писали «ничего не сохранено» - ввод в заблуждение.

### Фикс

- fetchIdentityVault: свой HTTP-запрос с кодом ответа; 200+error → ""
  (полка пуста), не-200/исключение → null (сеть/инфраструктура).
- restore: null → NetworkFailed («Нет связи с сервером. Попробуйте
  позже»), "" → NotFound (теперь это значит ровно «под ником пусто»).
- Сообщение NetworkFailed в онбординге уже было.

НЕ тронуто: ядро, E2E, механика сундука (IdentityVault: PBKDF2
210k/AES-GCM, ключ не покидает телефон), worker API.
