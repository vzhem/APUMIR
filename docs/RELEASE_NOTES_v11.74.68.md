# APU v11.74.68 — фикс ANR при пропавшей сети + оптимизация процессов

## Что изменилось

Владелец (2 скрина: ANR «Приложение "APU" не отвечает», настройки с
зависшими «проверяю…»/«Loading…»): «Версия 11.74.66 зависает и не даёт
обновиться 11.74.67… Нужно проверить все процессы и сделать оптимизацию».

Причина (аудит): NetworkChangeReceiver.onReceive - на ГЛАВНОМ потоке -
при КАЖДОЙ смене сети делал stopService + startForegroundService
(пересоздание всего стека: движок, подписки, bootstrap-синхронизации).
Ночью сеть прыгала: перезапуск за перезапуском, офлайн-старт копил
QUIC-таймауты (до 5-10 с на send, см. комментарий RustBridge.sendMessage)
- «Приложение не отвечает». Утром сеть стабильна - «всё работало».

Исправления:
1. NetworkChangeReceiver: дебаунс 10 с (prefs apu_network_rx) + перезапуск
   сервиса в фоновом потоке через goAsync; главный поток - только лог.
2. RustBridge.isNetworkUp(): активной сети нет - синхронизации каталогов
   (StickerLibrary/GifLibrary.syncWithSwarm) не стартуют вовсе; дедлайн
   8 с на цикл по собеседникам - связь, пропавшая посреди синка, не копит
   блокировки за движком.
3. Мелочи с главного потока - в IO: чтение файла стикера
   (GroupChatViewModel.sendSticker), запись recents (ChatDetailViewModel
   .sendSticker).

Аудит без изменений: текстовые/файловые отправки уже в IO (раунд 120);
pingHealth - IO с таймаутами; AvatarBitmaps - IO/Default; PumpOutgoing -
IO.
