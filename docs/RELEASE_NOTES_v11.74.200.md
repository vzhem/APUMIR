# APU v11.74.200 — доставлено — значит, свободно: резерв «своих» разгружается

## Что было не так

В отчёте «Логи» по v11.74.199 видно:

```
Relay-очередь: своих=1000 сигналов=0 чужих=1583
MQTT: delivery ACK received for <id>
```

Число «своё ждёт получателя = 1000» упиралось в предел и **не снижалось**, хотя
собеседник постоянно подтверждал доставку («delivery ACK received»). При этом
«сигналов=0» — значит резерв был занят настоящей перепиской, а не служебными
сигналами (это починили уже в v11.74.198).

## В чём причина

Подтверждение доставки приходило двумя разными путями, и они были неравны:

- **прямой ACK** (обычная доставка) — только зажигал вторую галочку;
- **receipt** (доставка через сеть) — зажигал галочку **и снимал сообщение
  с удержания**.

Из-за этого каждое сообщение, доставленное обычным путём, навсегда оставалось
в резерве «своих» и в хранилище — до самого конца срока хранения. Когда резерв
заполнялся (1000), ради нового сообщения вытеснялось самое старое — то есть под
удар попадало именно то, что ещё не дошло до собеседника.

## Что сделано

- **Доставлено — свободно.** Прямое подтверждение теперь снимает сообщение
  с удержания: и из рабочей очереди, и из хранилища (со «надгробием», чтобы
  запись не ожила после перезапуска).
- **Чужую пересылку не трогаем.** Снимается только своя переписка: чужой
  конверт подтверждают не нам, его нельзя удалять по чужому номеру — иначе
  сосед по сети потеряет пересылку.
- **В журнале виден результат.** В минутной строке очереди появилось
  `снято-по-ACK=N`, а каждое снятие пишет отдельную строку:

```
Relay-очередь: своих=12 сигналов=3 чужих=1583 всего=1598 получателей=7 снято-по-ACK=27
MQTT: delivery ACK снял <id> с удержания (своё доставлено)
```

- **Закреплено тестом и контрактом** — снятие «своей» записи, чужая остаётся,
  повтор и незнакомый номер безопасны.

## Что это меняет на телефоне

Обмен сообщениями и галочки выглядят как раньше. Меняется поведение резерва:
он больше не заполняется доставленным. Накопленное до этого обновления
(у вас — 1000) уходит постепенно: по сроку хранения (24 часа для фото, видео и
всего тяжёлого, 7 суток для текста) и когда собеседник подтверждает повторно.
Новые сообщения копятся только пока не подтверждены.

## Отдельно: «не вскрылось 29»

Это не сбой очереди, а **рассинхрон ключа** с собеседником: он шлёт сообщения
на старый ключ, поэтому они не могут расшифроваться. Плашка и кнопка для этого
уже есть в v11.74.198, но «починить» это за собеседника нельзя — сброс
происходит только при пересканировании QR-кода. Пока оба не пересканируют —
такие сообщения будут появляться; после — прекратятся.

`last_error = Websocket: HTTP error: 500` — разовый отказ моста; прямой путь
при этом оставался жив (`Connected=true`), достаточно повтора.

## Что дальше

строки списка чатов.
