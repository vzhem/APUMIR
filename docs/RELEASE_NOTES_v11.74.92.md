# APU v11.74.92 — прокси: кнопка «удалить нерабочие» работает, список 500

## Что изменилось (раунд 196)

Владелец: «раздел прокси посмотрим... выводимый список сократить хотя бы
до 500. И нужно чтобы удаление не рабочих прокси по кнопке работало».

### Диагноз кнопки

dao.cleanupDead требовал (now - lastCheck) > 7 дней при failCount >= 3,
но healthcheck (incFailCount) обновляет lastCheck при КАЖДОЙ попытке -
условие почти никогда не истинно, кнопка всегда писала «Удалено: 0».

### Фиксы

1. MtProtoProxyDao.deleteDeadNow(): DELETE ... WHERE failCount >= 3 AND
   source != 'MANUAL' - удаляет сразу всех, кого экран показывает как
   «✗ Нерабочий (N fail)». Ручные не трогаются (удаление по одному с
   карточки, как было). Repository.cleanupDeadNow(), VM.cleanupDead()
   -> новый метод, честный итог («Нерабочих не нашлось» при нуле).
2. Список на экране - 500 лучших: VM берёт proxies.take(500) из
   observeAll (сортировка в DAO: isActive DESC, successCount DESC,
   lastCheck DESC). В UiState +totalInPool; над списком плашка
   «Показаны 500 лучших из N в пуле» (только когда N > 500). Пул
   целиком остаётся для автопилота (enforcePoolLimit(500) у сборщика
   уже был - теперь и экран не рисует тысячи карточек).

Для чего прокси (вопрос владельца): запасной туннель для «жёстких»
сетей - публичные MTProto-прокси как TCP-релеи, лучший по отклику
кормится ядру (SOCKS5-мост сигнального MQTT, ProxyAutopilot: цикл
проверить-удалить-выбрать-лучшего, мгновенная чистка при fail>=2,
переключатель «Туннель через прокси»). Сбор - TelegramChannelScraper
(GitHub + каналы, раз в 6 ч, с ранга 20). На обычной сети не активен.

НЕ тронуто: ProxyAutopilot, сборщик, healthcheck, ядро, E2E.
