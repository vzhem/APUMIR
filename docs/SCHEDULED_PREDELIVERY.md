# Предварительная доставка и отложенный показ текста

Реализовано в PR #46 и выпущено в v11.74.355; PR не слит.
Сборка и границы проверки: [RELEASE_AUDIT_v11.74.355.md](RELEASE_AUDIT_v11.74.355.md). Это развитие общего выбора даты/времени,
а не изменение серверной очереди. Личные чаты, группы, темы и каналы используют один
планировщик; вложения по-прежнему не планируются.

## Протокол и совместимость

1. Новая запись ScheduledSendStore немедленно получает early-work и отдельное due-work.
   Существующие записи без `preDeliver` остаются sender-timed, чтобы обновление не меняло
   смысл уже созданных заданий. Ошибки больше не удаляют задание после трёх попыток.
2. Адресату посылается маленький зашифрованный `APUGRP1|deferprobe1|id|digest`.
   Старые клиенты с GroupWire (в том числе v11.74.354) поглощают незнакомый вид без
   сообщения/уведомления. Только после `deferready1` отправляется тело `defer1`.
   READY — совместимость, **не** подтверждение сохранения.
3. Данные и ответы идут через RustBridge.sendMessage / существующий fail-closed
   MessageSealer. При отсутствии ключей открытый текст в relay не отправляется.
   Служебные конверты перехватываются до создания контакта и до записи сообщения
   в основном, CF-резервном и зеркальном путях. Они также имеют уже зарезервированный
   префикс APUGRP1 последнего стража ChatRepository.
4. Получатель проверяет пакет и права группы, фиксирует скрытую запись в отдельной SQLite
   и ставит локальный WorkManager-таймер. Только затем посылается `deferack1|id|digest`.
   Копия в relay/на соседе и обычный transport ACK не увеличивают счётчик скрытых копий.
5. Отправитель принимает stored receipt только от адресата из сохранённого списка,
   для совпадающих логического ID, хэша **всего** содержимого/времени и своей личности.
   После успешного MessageSealer.open проверяется также совпадение узла подписанной
   sender binding с транспортным senderId: участник группы не может подписаться за другого.
   Точное соответствие ID такое же, как у файлового обмена; неизвестные alias-ID не
   подтверждают раннюю копию (остаётся обычный fallback после срока).
   В группе подтверждения отдельные для каждого адресата. До срока нет статуса «прочитано».
6. После срока неподтверждённым адресатам идёт обычный совместимый текст/групповые пакеты.
   До срока этот fallback запрещён. Логический ID тот же, транспортные ID ранней доставки,
   обычной доставки, частей и разных получателей различаются. Обычные ACK после срока
   завершают только fallback, не маскируются под stored receipt. Все попытки сохраняются,
   обход получателей ограничен восемью за проход и циклический: офлайн-участники не
   должны навсегда задерживать остальных.

## Скрытое хранение и показ

- `noBackupFilesDir/deferred_inbox.sqlite`, отдельный от Room файл; текст AES-256-GCM,
  ключ в Android Keystore, AAD привязывает шифротекст к записи. В чатах, поиске,
  превью, непрочитанных и обычной синхронизации истории записи отсутствуют.
- Записи разделены по локальному владельцу/отправителю/ID. Повтор идентичного пакета
  идемпотентен, изменение уже сохранённого ID не принимается. Выполненная запись
  остаётся компактным tombstone без тела: повтор не воскресит удалённый текст.
- До 128 скрытых записей одного отправителя и 2048 на локальную личность.
  При переполнении отказ **без stored ACK**, без вытеснения сохранённых сообщений.
  Тело ограничено 34 000 байт, весь открытый проводной пакет — 34 500 байт,
  с запасом на шифрование/base64 и последующий base64 внутри 64 KiB mesh-envelope.
  Текст — последнее поле с ограниченным split, поэтому разделители/переводы строк
  сохраняются без третьего base64-расширения большого тела.
- DeferredRevealWorker не имеет сетевого ограничения и перед показом повторно сравнивает
  текущие часы с фиксированным showAtMs. Он записывает сообщение, обновляет штатные
  счётчики и вызывает NotificationHelper с сохранением mute/quiet/topic.
  Наличие движка Rust/соединения для локального показа не требуется; для групп
  локальная личность явно берётся из сохранённых настроек, не из работающего ядра.
- Сервисный observer не дублирует уведомление скрытого inbox: оно принадлежит reveal.
  Insert-ignore защищает счётчики от одновременного fallback и локального раскрытия.
- При старте приложения восстанавливаются задания отправителя и таймеры скрытого inbox
  (в том числе после сбоя между SQLite commit и enqueue). WorkManager сохраняет задания
  между перезагрузками. Сервис дополнительно помогает очереди каждые 30 секунд.
- WorkManager использует HiltWorkerFactory из Application; его автоматический reflection
  initializer отключён в manifest. Раньше такой конфигурации у Hilt-workers не было.
- Для зеркального устройства отправителя при необходимости запрашивается роль движка,
  как в файловой отправке; ранний текст не записывается ради пересылки в видимую историю.

## Пользовательский смысл и ограничения

В меню до подтверждения написано, что передача начинается заранее. Баннер показывает
`Скрытая копия сохранена: N из M`, где N — только stored receipt. При ошибке подготовки
она видна в баннере, задание сохраняется. Список участников фиксируется при первой
успешной подготовке; новый участник не считается заранее получившим сообщение.

По следующему уточнению владельца отмена доступна и после предварительной передачи.
До начала передачи запись убирается локально. После начала атомарно сохраняется
`cancelRequested`, отключаются отправка/раскрытие/обычный fallback, создаётся отдельное
немедленное задание отмены. Запрос хранится и повторяется до специального подтверждения
каждого адресата; обычный transport ACK не выдаётся за подтверждение отмены.
В баннере виден именно запрос, а не обещание успешного удаления у всех.

Новые зашифрованные конверты `defercancel1`/`defercancelack1` привязаны к полному digest,
ID и проверенному подписанному отправителю. Получатель сначала сохраняет sender-scoped
cancel tombstone, затем стирает скрытое тело и, если текст уже появился, его собственную
строку/части/реакции и относящееся к ней уведомление. Остальные авторы, комментарии,
темы и более новые уведомления не удаляются. Завершение очистки фиксируется отдельно;
сбой между tombstone и очисткой восстанавливается без ожидания нового соединения.
Входящий cancel до данных подавляет запоздалые ранние копии, normal fallback,
части длинного текста и зеркальную/групповую досылку. Конкурирующий таймер не может
снять маркер отмены. Sender completion проверяет cancel intent под тем же lock,
чтобы не выбросить запрос при гонке с завершением отправки.

Локальная отмена не может остановить уже находящийся в пути пакет на чужом узле.
После срока дополнительно отправляется совместимая команда обычного удаления для
личного/группового fallback. Для канала старый формат не используется: старый клиент
может удалить всю тему поста вместе с чужими комментариями. Отсутствие нового cancel ACK
оставляет запрос неподтверждённым. Повтор cancel/ACK явно обновляет native relay retention
через retryMessage, сохраняя тот же ID, чтобы истечение TTL не обрывало durable-запрос.
Предельные случаи старого клиента/перестановки пакетов/уже прочитанного сообщения —
**best effort**, а не гарантия удаления. Для неизвестных cancel ID есть предел
1024 маркера на отправителя и 16384 на личность; при исчерпании нет ложного ACK.

После подтверждённого сохранения получатель может увидеть сообщение без сети,
даже если отправитель уже офлайн. Если сохранения не было, для fallback всё ещё нужна
сеть после срока. Android/Doze/force-stop/выключенный телефон могут задержать показ;
точность до секунды не обещается. Время — абсолютный instant; смена часового пояса
его не переносит. Неверные часы получателя влияют на локальный момент показа.
Права группы повторно проверяются при показе: удалённый/заблокированный участник
не должен получать прежние отложенные публикации через этот путь.

Это скрытие до срока в штатном клиенте, **не** криптографическая time-lock-защита
от владельца изменённого клиента: данные и ключ уже находятся на его телефоне.
Скрытый inbox не переносится резервной копией на другое устройство. Удаление приложения,
очистка данных или потеря Keystore уничтожают доступ к локально сохранённой копии.
Сбой между уведомлением и отметкой complete может повторить уведомление после перезапуска;
exactly-once для системной шторки не заявляется.

## Проверки

- 12 DeferredWireTest: RU/Unicode/разделители, личка/группа, старый parser, tiny probe vs
  READY vs stored receipt, привязка digest, неверные/слишком большие пакеты,
  точная граница времени/поздний показ/часы назад, стабильные ID фаз/адресатов/частей,
  размер sealed + relay base64 при максимальном конверте и bounded-разбор
  sender binding из ключевого конверта, независимые cancel/cancel-ACK и части.
- 3 DeferredDeliveryPolicyTest: чужой адресат/личность/хэш/ID не подтверждают копию,
  per-recipient fallback и ограниченный циклический обход.
- Оба набора подключены к чистому Kotlin runner и Android JVM testDebugUnitTest.
- 9 DeferredInboxStorageInstrumentedTest для настоящих SQLite + Android Keystore:
  перезапуск, идемпотентность/коллизия/tombstone, другая личность, повреждение,
  квота без потери прежних записей; cancel до/после данных и показа, повтор,
  другой отправитель, stale completion, восстановление cancel marker.
  Изолированные файл, prefs и key alias.
  Эти device-тесты написаны, но **не запускались** в песочнице без Android-устройства.
- Локально: style (15), unresolved-symbols, XML RU/EN+manifest, bash syntax, diff check.
  Компиляция и JVM-тесты выполняются CI PR #46; предыдущий зелёный прогон выбора
  даты/времени не является результатом проверки предварительной доставки.

Обязательная проверка на двух телефонах перед релизом:
1. Выбрать время через 2–3 минуты, дождаться 1/1 hidden stored; до срока проверить
   чат/поиск/превью/шторку/счётчики на получателе — нигде нет текста.
2. Отключить сеть на ОБОИХ телефонах; в срок проверить текст/порядок/уведомление/mute.
3. Повторить с перезапуском процесса, перезагрузкой, Doze и выключенным телефоном;
   отдельно проверить обратный перевод часов и смену часового пояса.
4. Группа/тема/канал: смешанные версии и онлайн/офлайн-участники, длинный текст,
   quiet, роли/закрытая тема/удалённый участник; счётчики и дубликаты частей.
5. Старый v11.74.354: до срока только probe без текста/шторки, после срока fallback.
6. Потерянный READY/stored receipt/обычный ACK, повтор и гонка fallback/reveal.
7. Зеркала обеих сторон, смена роли, полный перезапуск отправителя после подтверждения.
8. Прежние sender-timed задания, отмена до/после начала и неподтверждённый запрос без связи,
   нехватка места/Keystore error: не показывать ложное подтверждение и не терять очередь.
