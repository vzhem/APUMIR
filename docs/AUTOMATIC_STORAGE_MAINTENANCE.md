# Автоматическое обслуживание хранилищ — v11.74.358

## Что управляется автоматически

- Native relay: отдельная задача через 5 секунд после запуска ядра, далее каждые 5 минут. Не зависит от подключения MQTT, gossip или открытия «Логов». Синхронный SQLite обслуживается через `spawn_blocking`, с тем же mutex, что и отправка; при занятом соединении проход пропускается. RAM expiry обслуживается здесь же.
- Истёкшие relay-записи V1/V2 и карантин: максимум 5000 строк каждой таблицы за проход. Удаляется только истёкшее по явной метадате, не по предположению о содержимом шифротекста. Собственные **действующие** записи не вытесняются ради свободного места; телефонная история/очередь исходящих этим кодом не очищается.
- Отметки доставки: храним максимум wire TTL (сейчас 7 суток) + сутки replay grace. Удаляем только старые, максимум 5000 за проход. Числовой лимит больше не выбрасывает свежие replay guards. Повторы сохраняют возраст первой отметки; cleanup отсутствующей записи не создаёт новый маркер.
- Короткоживущие сигналы: до шифрования помечаются только typing и allowlist служебных команд GIF/sticker (`ask/have/want/thumb/thmb`). Retry того же caller ID/получателя сохраняет transport ID; пользовательские сообщения, `ref`, удаление и другие durable-команды сохраняют прежние ID. Тело остаётся запечатанным; политика отказа при отсутствии ключей не ослаблена. Native держит распознанные сигналы в отдельном ограниченном RAM-резерве на 5 минут, не сохраняет их в durable и не оставляет для них постоянные локальные маркеры. Распознанные файловые пакеты также остаются transient (не путать с durable состоянием самой передачи).
- Приём **новой чужой** переписки прекращается при 20 000 суммарных encrypted relay-строках или 256 МиБ занятых страниц relay-базы. Учитываются и уже занятые другими relay-таблицами страницы. Никакая действующая запись для этого не удаляется. Собственная переписка продолжает пользоваться защищённым путем `store_encrypted`, не этим admission gate. Это ограничитель чужой нагрузки, **не общий предел размера приложения**, не квота истории/личных документов и не замена ползунку файлового хранения.

## Реальное уменьшение файлов SQLite

Новые relay-базы создаются с incremental auto-vacuum. Старые NONE-mode базы мигрируют через SQLite VACUUM **только** когда свободно ≥64 МиБ страниц, они занимают ≥половины базы, доступно >двойного размера базы +64 МиБ временного места, а последняя попытка была ≥сутки назад. Возраст попытки хранится в отдельной числовой служебной строке и переживает перезапуск.

На SQLite-работу всего прохода установлен progress interrupt после 5 секунд; busy timeout обслуживания — 100 мс (обычным записям возвращается прежний 5-секундный timeout). Остановка ядра посылает SQLite interrupt перед повторным открытием, чтобы старая blocking-задача не оставляла миграцию нового экземпляра без durability. Это не жёсткая гарантия против задержки ОС/fsync. Прерванный VACUUM использует транзакционную защиту SQLite, не подменяет БД и не удаляет её файлы. Дальше incremental-vacuum освобождает ограниченные партии страниц. WAL checkpoint/TRUNCATE выполняется только самим SQLite: читатели могут отложить его, вручную DB/WAL/SHM не удаляются. `journal_size_limit` ограничивает остаточный WAL после сброса, но не запрещает нужный живой WAL.

Около гигабайта на старом телефоне не обещаем убрать мгновенно: часть страниц может освобождаться сразу при успешной compaction, старые маркеры — партиями, свежие и действующие данные сохраняются. При недостатке места/времени/занятом соединении обслуживание переносится. В RAM-only режиме недоступная старая durable-база не вскрывается ради уборки; эта версия **не исправляет** отдельно исследуемый сбой unwrap ключей.

## Файлы Android

WorkManager: проход через минуту после запуска приложения и периодическая работа раз в 6 часов без требования сети. Android может задерживать фоновые задачи; после принудительной остановки обслуживание возобновится с запуском приложения. Временная часть дополнительно ограничена 10-минутным интервалом.

- Разрешены только app-owned временные корни `story-camera`, `story-source`, `shared`: листовые копии старше 7 суток.
- В корне cache удаляются только старые `apu_pick_*.apk` / `gif-mirror-*.gif`, без рекурсии. В GIF/sticker-библиотеках — только старые промежуточные `.tmp`, не сами изображения/каталог.
- В encrypted file-transfer root допускаются только старые скрытые атомарные `.tmp`, не chunks/manifest/key-envelope. Каждый корень: ≤4096 рассмотренных entries, ≤128 удалений и 200 мс budget; symlinks не обходятся, future/неизвестные timestamp сохраняются.
- Передачи: прежняя политика тяжёлых данных 24 часа/малых 7 суток сохранена. Периодический worker и насос независимо от сетевой отправки запускают безопасную expiry-уборку. Обход transfer-директорий ограничен 4096 entries, физические копии — 128 за проход; неудачное удаление оставляет expired DAO-row для следующей попытки. Sender/receiver защищены общими mutex; занятая передача переносит уборку, а не блокируется ею. Просроченные незавершённые удаляются по прежней политике; у завершённых удаляется только истёкшая encrypted relay-копия, **полученный документ и его история остаются**.
- Orphan: ошибка DAO = «неизвестно», **не** «строки нет». Успешно подтверждённому orphan-директорию дополнительно даётся 7 суток создания, чтобы не удалить подготовку до записи строки.
- APK/DownloadManager: только MediaStore-строки, явно принадлежащие нашему package, старше суток; bounded scan 128. Самый новый ещё не установленный APK сохраняется. Установленный APK продолжает раздаваться из установленного приложения.

**Не очищаются по возрасту:** `voice` (может быть единственным источником сообщения истории), полученные документы, пользовательская история/фотографии, резервные копии, ключи идентичности/обмена и ключи действующих передач. Нет blanket cache/files/noBackup clear. Автоматически не вызываются ручные `purgeCompletedTransfers`/`cancelStalledOutgoing`.

## Наблюдаемость и проверки

«Логи»: числовая последняя сводка временной уборки/накопленные bytes и отдельно ограниченное окно native expiry/quarantine/old markers/compaction. Это не полный lifetime-журнал native и не доказательство отсутствия событий при нулевой выборке. Никаких имён документов или расшифрованных тел в новых событиях.

Регрессии: настоящий Rust/SQLite bounded expiry, fresh replay retention, first-seen markers, missing-ID cleanup, foreign admission/own preservation, физическое уменьшение legacy DB с живым AEAD-record, rollback прерванного VACUUM; JVM temporary age/symlink/limit/key/chunk preservation, orphan creation grace и ephemeral/ref ID contracts. Source-contract checks — дополнительная проверка wiring, не замена runtime-тестам. Android main/androidTest compilation и выбранные JVM tests входят в CI. Физический телефон/производительность flash/OEM WorkManager ещё требуют проверки; исправление истории не утверждает app-level ACK/показ у получателя или восстановление частично принятого фото после restart.
