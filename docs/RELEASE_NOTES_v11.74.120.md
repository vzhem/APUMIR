## Как работает

Настройки → Синхронизация → «Синхронизировать аккаунт»:

- **Телефон с данными**: ввести пароль «Защиты личности» → «Передать на
  другое устройство» → приложение собирает зашифрованную копию
  (.apubak, без медиа) и поднимает ОДНОРАЗОВЫЙ сервер на своём
  Wi-Fi-адресе. На экране: QR + код «192.168.x.x:48126» + 8-значный
  одноразовый токен. Копия отдаётся первому, кто назовёт код, после
  чего раздача закрывается.
- **Новое устройство**: ввести адрес и код с экрана телефона →
  «Забрать копию с телефона» → копия скачивается НАПРЯМУЮ с телефона
  (GET http://<адрес>/<код>) → показывается, чья копия и от какого
  числа → «Применить и перезапустить» (штатный путь файла-копии:
  stage → confirm → applyStagedIfAny). Случайный запуск ничего не
  подменяет.

QR можно сканировать ЛЮБЫМ сканером - payload
`apu://sync|<ip>|<port>|<token>` человекочитаем.

## Безопасность

- По сети идут только зашифрованные байты (архив заперт паролем
  человека); пароль по сети не ходит, нигде не хранится.
- Один токен = одна передача; сервер живёт только пока открыто окно
  (или до успешной отдачи/отмены).
- Ничего не хранится: ни в облаке, ни на сервере - только байты между
  двумя устройствами в одной Wi-Fi сети.

## Ограничения v1

- Оба устройства в одной сети Wi-Fi.
- Эмулятор/ПК может ЗАБИРАТЬ копию (исходящие соединения открыты);
  передать НА эмулятор без adb reverse нельзя - если источник телефон,
  на эмуляторе вводим адрес/код и забираем (это основной сценарий).
- Полученные медиа-файлы не переезжают; копия без медиа обычно 1-5 МБ.
- Автосинхронизация из р223 убрана: «постоянное зеркало» между двумя
  устройствами одного аккаунта требует изменения протокола (эхо
  исходящих в собственную тему) - это уровень ядра, отдельное решение
  владельца. Пока - перенос копией по требованию в обе стороны.
