# APU v11.74.86 — «Сообщения сети» по-человечески

## Что изменилось (раунд 190)

Владелец спросил, что значит пункт бэклога «очеловечить Сообщения сети»,
и выбрал «Да, сделай». Это строка-диагностика в Настройки → Сервер →
«Сообщения сети»: раньше она показывала сырую строку ядра
(«MQTT: tcp 1.2.3.4:8883, ConnAck 12 с назад, ошибка …»), а по тапу —
абзац жаргона (брокер, ConnAck, tcp/wss).

1. SettingsViewModel: mqttHuman - человекочитаемая версия той же строки.
   Ядро НЕ тронуто, разбор на стороне приложения; если формат строки
   изменится - вернётся пусто и экран покажет сырую, как раньше.
   - Статус по правилу «что произошло позже - то и состояние»:
     ConnAck позже ошибки → 🟢 «На связи (подтверждена N назад)»;
     ошибка позже → 🟡 «Перебои: заминка N назад — <причина>»;
     ConnAck ещё не было → 🟡 «Подключаемся…» / «Подключаемся с трудом».
     ConnAck приходит раз на (пере)подключение, поэтому «подтверждена
     N назад» = возраст текущей сессии, а не давность проверки.
   - Путь без адреса сервера (просьба владельца 2026-09-19, заодно
     р157): tcp → «напрямую», wss/наш брокер → «через обходной канал» /
     «через наш сервер (прямой путь не прошёл)», SOCKS5 → «через мост».
   - Ошибки переведены: refused → «узел не принял связь», timeout →
     «не дождались ответа», unreachable → «сеть до узла не доходит»,
     reset by peer/connection closed → «связь оборвалась», dns/lookup →
     «не удалось найти адрес узла»; незнакомое остаётся как есть.
2. SettingsScreen: подзаголовок строки = mqttHuman (fallback на сырую);
   диалог - human-текст + 2-3 простые фразы про автовыбор пути вместо
   абзаца жаргона; «Скопировать» кладёт human + СЫРУЮ строку (для
   диагностики в чате разработки), как и раньше - только теперь с обеими.

Проверено симуляцией на всех 6 реальных форматах mode из
mqtt_transport.rs (tcp, tcp+SOCKS5, wss-мост, наш брокер x3) и на
сочетаниях ConnAck/ошибка; пойман и исправлен дубль «назад назад».
