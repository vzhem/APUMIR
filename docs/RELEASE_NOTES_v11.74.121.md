# APU v11.74.121 — профили находят себя сами и сами синхронизируются

## Что изменилось (раунд 225)

Владелец: «нужно сделать чтобы профили находили себя сами и сами
синхронизировались. И нужно добавить возможность синхронизации через
любые мобильные сети». «Доделай чтобы синхронизация работала
автоматически и на всех сетях» — выпущено.

«Синхронизировать аккаунт» теперь работает сама и в любых сетях
(Настройки → Синхронизировать аккаунт), в дополнение к прямому
переносу по Wi-Fi из v11.74.120.

## Как работает

- **Находят себя сами.** Оба устройства с одним ником («Защита
  личности») адресуют одну полку сами: полка = отпечаток ника, ни
  адресов, ни кодов вводить не нужно. Код забора выводится из пароля
  копии прямо на телефоне — пароль по сети не ходит, вводить код
  никуда не нужно.
- **Любые сети.** Wi-Fi и мобильный интернет — через одноразовый
  релей `/psync` на воркере. Принцип р224 соблюдён: ничего не
  хранится — копия стирается сразу после забора (fetch-once) и в
  любом случае через сутки (KV TTL); по сети идут только
  зашифрованные байты архива (.apubak, без медиа, до 24 МБ).
- **Автоматика в обе стороны.** «Проверять самому автоматически»
  (один раз, на обоих устройствах):
  - источник сам выкладывает свежую копию на полку (и обновляет её,
    пока копию никто не забрал);
  - второе устройство само находит чужую копию, скачивает, готовит и
    присылает уведомление «копия готова — применить?».
  Применение всегда руками: профиль молча не подменяется.
- **Без спама и без затирания.** Копии на полке помечены nodeId
  устройства: свою копию устройство не тянет, устаревшую свою —
  обновляет. Манифест копии несёт дешёвый отпечаток данных (числа
  записей ключевых таблиц): одинаковые копии тишина, изменённые —
  уведомление. Приёмник, ещё не применивший чужую копию, свою пустую
  на полку не кладёт (не затирает оригинал).
- **По Wi-Fi напрямую** (без интернета) — как в v11.74.120: QR +
  адрес + код, приёмник забирает сам.

## Как перенести аккаунт

1. На устройстве с данными: Настройки → Синхронизировать аккаунт →
   пароль копии → «Отправить копию в сеть APU» (или включите
   автоматику — выложит сама).
2. На втором устройстве: тот же ник, тот же пароль → копия найдётся
   сама (или кнопкой «Забрать копию по паролю») → уведомление или
   «Копия готова» в окне → «Применить и перезапустить».
3. Получены чаты, контакты, сообщества, ранг, настройки. Получённые
   файлы (картинки, видео) остаются на исходном телефоне.

## Владельцу: обновить воркер (ОБЯЗАТЕЛЬНО)

Маршрут `/psync` живёт на воркере, у владельца пока старая версия:

1. dash.cloudflare.com → Workers & Pages → **p2p-relay** → Edit code.
2. Заменить ВЕСЬ код содержимым `tools/worker/p2p_relay_worker.js`
   из репозитория (коммит 036c884).
3. Deploy. Привязки (KV APU_VAULT, DO MQTT_BRIDGE) не трогаются.
   Деплой перезапускает MQTT-мост — 1–2 минуты мосты сойдутся.

Проверки после деплоя:
- `https://p2p-relay.1985vzhem.workers.dev/health` → `{"status":"ok"}`;
- `https://p2p-relay.1985vzhem.workers.dev/psync/<64 hex>?meta=1`
  → `{"error":"not found"}` (маршрут жив, полка пуста);
- `/update/latest` → v11.74.121 (если github 403 — это лимит GitHub
  API с IP Cloudflare, сам пройдёт).

## Технические детали

- Полка: `sha256("apu-sync-slot-v1|" + lower(nick без @)).take(32)`
  → KV `ps2:<hex>`, TTL 86400.
- Код забора: `sha256("apu-sync-code-v1|" + nick + "|" + пароль)
  .take(16)`; PUT несёт `X-Apu-Check = sha256(код)`, GET —
  `X-Apu-Code`; воркер сверяет sha256 и стирает все 4 ключа после
  забора. Пароль по сети не ходит.
- Устройство-владелец: заголовок `X-Apu-Device` (nodeId), виден в
  meta (`dev`).
- Отпечаток данных: `data_fp` в манифесте (незнакомые ключи старые
  сборки пропускают — совместимо в обе стороны).
- Авто-режим: WorkManager periodic 6ч (unique `profile_sync_auto`),
  пароль заперт Keystore (`apu_profile_sync_pw_v2`), уведомление в
  канале «Синхронизация аккаунта».
