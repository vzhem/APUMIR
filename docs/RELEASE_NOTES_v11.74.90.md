# APU v11.74.90 — азбука адресов: рой основной, сервер для первой загрузки

## Что изменилось (раунд 194)

Владелец: «Продолжай» (шаг 3 плана разгрузки из AI_HANDOFF 0y:
азбука адресов - роевые копии как основной путь, сервер - для первой
загрузки).

### restoreNowForce: приоритет переставлен

Кнопка «Восстановить» (Настройки → Сервер): сначала askSwarm (роевые
копии, механика р125 - сколько дали, все вливаются mergeIntoLocalBook),
и только если рой молчал - сервер (fetchAddressBook). Итог при обоих
провалах: «Рой молчал, на сервере копии нет - попробуйте позже».
Обычное восстановление не тратит запросы лимитированного воркера.

### Новое: autoRestoreIfEmpty (AddressBookBackup)

Если локальной азбуки нет (свежая установка, файл потерян) - молча
спросить рой и влить копии: раз в 6 часов (KEY_LAST_SWARM_RESTORE_AT,
SWARM_RESTORE_RETRY_MS), зовётся из часовой петли сервиса
(CoreServerService, рядом со swarmHourlyTick). Сервер остаётся для
restoreBeforeStart (до старта движка, когда роя у узла ещё нет).
Кандидаты для опроса - swarmPeerDirectory.audienceIds() (переживает
переустановку) + записи азбуки. Шифрование не тронуто (AES/GCM на
ключе личности), вливание - только добавление адресов.

НЕ тронуто: AddressBookSwarmBackup (ask/distribute/elect), тайминги
автокопии, ядро, E2E. Настройки: «Загружаю…» → «Спрашиваю рой…».
