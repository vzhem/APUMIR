# APU v11.74.37 — служебные конверты не падают в чат; уведомления открывают чат

## Что исправлено

### 1. «APUSTK1 ask» в переписке (на обновлённых телефонах)

Запасной путь приёма (резервный канал через Cloudflare) сохранял
сообщения в чат БЕЗ разбора служебных конвертов. Пока прямая связь
работала, конверты перехватывались; стоило ей мигнуть — и служебная
строка падала в переписку. Теперь запасной путь использует тот же
фильтр, что и основной (`routeIncomingEnvelope`): конверты стикеров,
гифок, удалений, реакций и прочей служебной почты до чата не доходят.
Конверт от неизвестного отправителя не создаёт чат.

### 2. Тап по уведомлению вёл на главный экран

В навигации сброс «куда вести» стоял первой строкой эффектa — он менял
ключ `LaunchedEffect`, корутина отменялась на первом запросе к базе, и
переход в чат не успевал случиться. Теперь: снять уведомление →
перейти в чат/тему → сброс последним (после него suspend-вызовов нет).

## Технические детали

- `service/CoreServerService.kt`: новый страж `routeIncomingEnvelope`
  (та же цепочка, что в `handleEvent/message_received`: файлы →
  гифк-ссылки → гифки → стикеры → группы → реакции → удаления →
  просмотры → сердечки → азбука → прочтения → рефералки → звонки);
  вызывается в CF-ветках `RelayEnvelope.Parsed.Message` и `.Other` до
  `saveIncomingMessage`; `getOrCreateChat` для конвертов не вызывается.
- `ui/navigation/NavGraph.kt`: порядок в `LaunchedEffect(pendingChatLink)`
  — cancelChatNotifications → navigate → onChatLinkConsumed последней.
