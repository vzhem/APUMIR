# M8 — чеклист проверки на телефонах (relay custody persistence)

> Тестируем постоянное зашифрованное хранение relay-очереди (этап M8):
> сообщение, которое посредник хранит для офлайн-получателя, должно пережить
> убийство процесса / перезагрузку и доставиться после пробуждения.

## Подготовка

- Три телефона: **A** (отправитель), **B** (посредник/relay), **C** (получатель).
  Имена в логах проекта — Анна/Женя/Стас, но суть та же.
- Собрать APK с новым Rust-ядром: `build-rust.bat` → `gradlew.bat assembleRelease -PreleaseVersionName=v11.17.0`.
- Установить поверх текущей версии **без удаления и без очистки данных**
  (`adb install -r`). Перед этим сохранить бэкапы.

## 1. Установка и сохранение данных (3/3)

- [ ] A, B, C: `adb install -r P2P-Messenger-v11.17.0.apk` — без ошибки downgrade.
- [ ] Приложение запускается без crash/ANR на всех трёх.
- [ ] `nodeId`/профиль не изменились (сравнить fingerprint до и после).
- [ ] Чаты и история сообщений на месте.

## 2. Основной сценарий M8 (посредник + убийство процесса)

1. [ ] C переводится в офлайн (авиарежим / выключить).
2. [ ] A отправляет сообщение для C. Маршрут: A → B (посредник), B кладёт
   сообщение в relay-очередь (custody).
3. [ ] На B в logcat видно: `Queued msg … for relay to …`.
4. [ ] **Убить процесс B**: `adb shell am force-stop com.vladimir.messenger`
   (или перезагрузить B — полный сценарий reboot).
5. [ ] Запустить B заново. В logcat должно появиться
   `Custody: восстановлено N сообщений для ретрансляции` (N ≥ 1).
6. [ ] Включить C (выйти из офлайна).
7. [ ] B доставляет сохранённое сообщение → C получает его.
8. [ ] A получает подтверждение доставки (статус `DELIVERED`).

## 3. TTL не сбрасывается

- [ ] Убедиться (по логам), что после восстановления custody у сообщения
  сохранён исходный deadline, а не «сейчас + 7 дней». Косвенно: сообщение
  доставляется, и в логах нет «восстановлено 0» при непустом файле.
- [ ] (Опционально, отдельный тест) положить сообщение в custody, перевести
  часы/ждать до истечения части TTL, перезапустить B, убедиться, что оставшийся
  TTL не увеличился.

## 4. Шифрование custody-файла

- [ ] Вытащить файл с B:
  `adb pull /data/data/com.vladimir.messenger/files/relay_custody.bin`
  (для debug-сборки можно `adb shell run-as com.vladimir.messenger cat files/relay_custody.bin`).
- [ ] Файл начинается с магического префикса `P2RC` (hex `50 32 52 43`).
- [ ] В файле **нет** читаемого текста сообщения / nodeId (binview/strings пусто).
- [ ] После изменения любого байта файла — приложение при старте пишет
  `Custody: не удалось загрузить` и продолжает работать с пустой очередью (не падает).

## 5. Регрессии

- [ ] Прямая доставка A→C в одной сети работает как раньше.
- [ ] MQTT fallback работает (получатель вне локальной сети).
- [ ] Нет шторма сообщений/ACK.
- [ ] Нет дублирующихся чатов после перезапусков.
- [ ] Обычная переписка (не через relay) не затрагивается custody.
