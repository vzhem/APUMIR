# APU v11.74.38 — уведомления приходят всегда; аварийный подъём через 5 минут

## Что изменилось

### 1. Почему уведомления «переставали приходить» — исправлено

Уведомление показывалось только если письмо «моложе 2 секунд» по часам
отправителя. Часы телефонов расходятся, письмо может ехать дольше двух
секунд запасным каналом — тогда уведомление молча гасло. Новый триггер:
оглашается всё, что пришло с момента запуска связи (включая
дождавшееся запуска), повторы гасятся по id, старые записи при
восстановлении бэкапа не звонят.

### 2. Аварийный каркас (экстренные вызовы)

- Системный будильник раз в 5 минут поднимает приложение, даже если
  процесс убит из «недавних» или усыпан системой (Doze).
- Аварийный минимум = CoreServerService: связь с сетью, приём писем,
  мгновенное уведомление; короткий каркас бодрости (wake lock 20 с).
- Точный будильник (setExactAndAllowWhileIdle); без права на точный —
  неточный в окне обслуживания Doze. Переживает перезагрузку
  (BOOT_COMPLETED).
- Тап по уведомлению открывает приложение полностью.

### 3. Запасной путь — без молчаливых потерь

Каждый служебный страж в защитной обёртке: падение разбора не съедает
письмо — оно доезжает до чата и уведомления.

## Технические детали

- `service/EmergencyKeepAlive.kt` (NEW): приёмник будильника и загрузки,
  `scheduleNext()` — самоподдерживающаяся цепочка «сервис перевзводит
  будильник, будильник стартует сервис»; права `RECEIVE_BOOT_COMPLETED`,
  `SCHEDULE_EXACT_ALARM` (12), `USE_EXACT_ALARM` (13+).
- `service/CoreServerService.kt`: onStartCommand перевзводит будильник;
  триггер уведомлений — база старта сервиса (минус 2 минуты) + множество
  оглашённых id вместо окна 2 с; `routeIncomingEnvelope` — каждый страж
  в runCatching.
