# Расширенная диагностика v11.74.356

## Что измеряется

Все новые метрики доступны через Настройки → Логи → Обновить → Скопировать/Отправить.
Они локальны: серверная телеметрия и автоматическая отправка не добавлены.

- **Сеть:** возможности активной сети Android INTERNET, VALIDATED, CAPTIVE_PORTAL;
  VPN, тарификация, активность Private DNS, статус Data Saver (1=off, 2=whitelisted,
  3=enabled), ограничение фоновой работы. Скорости link_* — оценки Android, не
  результаты speed test. VALIDATED не доказывает доступность собеседника/брокера.
  Журнал возможностей слушает все подходящие сети: потеря одной не означает потерю
  активного подключения. Адреса, SSID, DNS-серверы и network IDs не добавляются.
- **Хранение:** см. [RELAY_STORAGE_DIAGNOSTICS.md](RELAY_STORAGE_DIAGNOSTICS.md).
  Физический размер SQLite/WAL/SHM не равен размеру живых сообщений; лимит файлового
  буфера не является квотой SQLite. Настоящая причина роста на тестовых телефонах
  пока не установлена: нужен новый отчёт с каждого устройства.
- **Отзывчивость UI:** одна проба Main Looper в секунду, только пока Activity started
  и экран интерактивен; максимум одна ожидающая проба. При уходе в фон/выключении
  экрана проба отбрасывается. Используется uptime (сон не включён). Порог 1500 мс;
  overdue учитывается один раз на пробу; предупреждение не чаще раза в минуту.
  late_completed и overdue могут описывать одну пробу — их нельзя складывать.
  Это детектор задержки, не доказательство ANR и не профилировщик причин.
  Таймер в фоне отменяется; проверка интерактивности выполняется без wake lock.
- **Служебные циклы:** обработка пакета событий ядра, file/group/APK pumps, личное/
  групповое удаление, повтор офлайн-отправки, сбор фактов/логов/аудит БД и проверка
  режимов ключей. Завершения, ошибки, отмены, последнее/максимальное время, текущие
  операции и возраст последнего завершения. completed включает failed/cancelled.
  Длительность включает ожидание IO/очередей, а не только CPU. In-flight не равен
  зависанию. Только фиксированные enum-метки; до 32 одновременных замеров, остальные
  считаются dropped. Не все функции приложения инструментированы.
- **Память:** Java heap (прежний отчёт), native heap, process PSS, число/уровень
  onTrimMemory. UI_HIDDEN тоже вызывает trim — это не обязательно нехватка памяти.
  PSS и история завершений читаются только по запросу отчёта, не каждую секунду.
- **Предыдущие завершения:** последние три доступные записи ApplicationExitInfo
  на Android 11+: ANR, crash, native crash, low memory, user requested, other;
  возраст и importance. На старых версиях явно unsupported. Без описаний, stack
  traces, PID и имён процессов. Это история ОС, не полный журнал всех сбоев.
- **Режимы ключей:** один отдельный daemon worker, общий бюджет ожидания до 1500 мс
  для двух read-only mode(). Застрявший Future сохраняется: повторное обновление
  не плодит блокированные потоки. Timeout не прерывает KeyMint/provider и не
  доказывает повреждение ключа. mode() может читать/разворачивать существующий
  локальный seed/secret для проверки доступности и обнуляет временный массив;
  сам ключ и binding в отчёт не попадают. Создание/сброс ключей и расшифровка
  переписки/relay payload диагностикой не добавлены. Другие вызовы сбора фактов
  не получили общего жёсткого таймаута.

Счётчики/тайминги/UI-пробы относятся к текущему процессу и сбрасываются после его
смерти. Журнал ограничен прежними 400 событиями; UI показывает последние 40;
logcat — ограниченная, редактируемая выборка. Диагностика не является бесконечным
архивом и не гарантирует фиксацию последнего события перед убийством процесса.

## Как собрать сравнимые данные

1. Обновить все тестовые телефоны до одной версии, не очищая данные и ключи.
2. С каждого телефона скопировать полный отчёт сразу после обновления — baseline.
3. Воспроизвести обычный обмен, переключение Wi-Fi/мобильной сети и уход в фон.
4. При росте места или задержке открыть Логи → Обновить → Скопировать. После
   падения/ANR перезапустить и также собрать отчёт: в нём может быть запись ОС.
5. Передать отчёты с условными подписями «телефон A/B» и кратким временем/сценарием.
   peer-N в аудите пересоздаются при каждом отчёте: между телефонами не сопоставлять.

Не удалять SQLite/WAL и не сбрасывать ключи ради проверки. Снимок БД может быть
частичным/несогласованным из-за параллельной работы; это явно отмечается в отчёте.

## Проверки и границы доказательств

RuntimeHealthTest проверяет исходы/длительности/предел активных замеров, защиту
от повторного/чужого ticket, единственную UI-пробу, порог, одноразовый overdue,
сброс при невидимости, старые callbacks и ограниченный renderer истории ОС.
DiagnosticsReportTest проверяет включение новых секций/сетевых статусов в отчёт.
Pure Kotlin/JVM-тесты включены в standalone runner и Android CI-фильтр.
Source guards проверяют wiring/ограничения/запрещённые поля; они не заменяют
Android-тестирование таймера, lifecycle и vendor KeyMint. Компиляция Android и
JVM-тесты проверяются CI; эмулятор/телефоны здесь не запускаются.

## Что добавить следующим этапом (не реализовано этим релизом)

1. Жизненный цикл сообщения send → persisted → route attempt → recipient ACK:
   агрегированные latency buckets/p50/p95, retry/cancel outcomes без текста и IDs.
2. Суточные дельты физических/живых байтов по хранилищам, expiry/eviction/ACK cleanup,
   давление квот и возраст старейшей доступной записи. Для зашифрованных столбцов
   не выдавать недоступные поля за известные и не расшифровывать их в диагностике.
3. Передачи: полезная скорость, число повторов/таймаутов, переключения маршрутов,
   время ожидания получателя и доля успешного возобновления.
4. Запуск/восстановление после фона: время до ready, рестарты сервиса/worker,
   энергопотребление и wakelock duration — с фиксированными ограниченными метками.
5. Ограниченный crash-safe журнал фаз (не содержимого) отдельно от logcat,
   opt-in retention/export и лимит байтов, чтобы логи сами не раздували хранение.
