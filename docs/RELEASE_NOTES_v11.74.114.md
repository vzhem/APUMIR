# APU v11.74.114 — приглашение-карточка: Вступить / Подписаться / Скачать APU

## Что изменилось (раунд 218)

Владелец прислал три замечания по приглашениям:
1. «В присланном сообщении нет кнопок подписаться, вступить, скачать».
2. Вместо «пригласить в группу» — «пригласить в сообщество».
3. «Убери личную информацию 1985vzhem» (адрес сервиса и GitHub в сыром виде).

## Итоговое поведение

**Карточка мульти-приглашения** (было: сырой текст с тремя ссылками и
«Скачать APU:»):
- заголовок «Приглашение в сообщества»;
- по блоку на каждое сообщество: название, подпись «Канал»/«Группа»,
  золотая кнопка «Подписаться» (канал) / «Вступить» (группа);
- ниже кнопка «Скачать APU» (установочный файл);
- сырые ссылки из видимого текста УБРАНЫ — это и снимает вопрос
  с адресом сервиса в пузыре.

**Одиночная карточка** (р189) — добавлена кнопка «Скачать APU», если в
тексте приглашения есть установочная ссылка (внешние тексты, пересланные
в чат); исправлен выбор ссылки: раньше бралась ПОСЛЕДНЯЯ ссылка текста
(получалась загрузка APK вместо «Вступить»), теперь первая.

**Переименование**: «Пригласить в группу» → «Пригласить в сообщество» —
меню контакта (ContactsScreen), заголовки диалогов и системного меню
«Поделиться» (AppShare, ChatListScreen, GroupsScreen). «Пригласить в
канал» не тронуто (канал остаётся каналом).

**Установочная ссылка** (AppShare.INSTALL_LINK): GitHub
(`github.com/vzhem/APUMIR/releases/latest/download/app-release.apk`)
→ воркер `https://…/update/apk` (раунд 157: APK отдаёт воркер). В чате
ссылка не видна вовсе (карточка); наружу («Другим приложением») уходит
адрес воркера — без GitHub.

**Новый формат текста мульти-приглашения**: «Присоединяйся к моим
сообществам в APU.» + блоки `Канал «Название»:` / `Группа «Название»:`
со ссылкой в каждом (признак канала теперь доезжает до получателя —
GroupRepository.inviteRefsFor). Старые форматы парсятся тем же
парсером: блоки без «Канал/Группа» получают кнопку «Вступить» (вход
всё равно определяет правильный тип по ссылке).

## Механика

- `GroupInviteCardSender.parseMultiCard` + `MultiInviteCard` +
  `GroupInviteRef` (title, link, isChannel).
- `GroupRepository.inviteRefsFor` (признак канала); старые
  inviteLinkFor/inviteLinksFor не тронуты (ChatList/Groups ViewModel).
- `MessageBubble`: multiCard-ветка ПЕРЕД одиночными карточками;
  `MultiInviteCardView`; `openInstaller` (ACTION_VIEW для APK-ссылки).
- Проверено зеркалом на Python: старый формат со скриншота (3 блока без
  флага + GitHub-ссылка), новый формат, одиночный внешний текст, формат
  build() — все распарсились верно; простое сообщение карточкой не стало.

## Не тронуто

Ядро, E2E, wire-протокол, custody-гейты р215–217, ContactCardSender,
QR-приглашение (р213). Адрес сервиса в БАЗЕ и внешних текстах остаётся
(абсолютные ссылки нужны для работы вне APU); полностью спрятать его
можно только своим доменом на воркере — по слову владельца (CF
dashboard).
