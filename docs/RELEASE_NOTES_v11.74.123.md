# APU v11.74.123 — реакции, удаления и прочтения тоже видны на обоих устройствах

## Что изменилось (раунд 227)

Продолжение живого зеркала (v11.74.122). Раньше между устройствами одного
аккаунта ходили только тексты; теперь — и служебные события переписки:

- **реакции** (значок появляется и снимается одинаково на обоих);
- **«удалить у всех»** — сообщение исчезает на обоих, превью чата
  пересчитывается;
- **просмотры постов канала** — счётчик сходится;
- **сердечки профиля** — счётчик сходится;
- **прочтения** — мои сообщения помечаются прочитанными на обоих;
- **ссылки на гифки** — карточка гифки приходит в переписку обоих.

Правило то же: сеть ведёт одно устройство, второе живёт его событиями.
Служебные конверты запечатаны на самого себя (воркер видит только маршруты),
в ответ тень ничего не отправляет — подтверждения делает активное
устройство.

Что ещё впереди (по плану `docs/MIRROR_FULL.md`): действия с второго
устройства (поставить реакцию, удалить, отметить просмотр), группы и каналы,
файлы и медиа (байты пойдут прямым каналом между устройствами), звонки.

## Владельцу

1. **Синхронизация не заработает без деплоя воркера** — это по-прежнему
   первое действие: dashboard → Workers & Pages → p2p-relay → Edit code →
   вставить весь `tools/worker/p2p_relay_worker.js` из репозитория → Deploy.
   Тот же деплой нужен и для v11.74.121/v11.74.122 (`/psync`, `/mirror`).
2. Проверка на телефонах — чек-лист `docs/MIRROR_SYNC.md` §7 плюс новые
   пункты: поставить реакцию с телефона друга и убедиться, что значок
   появился на обоих устройствах; «удалить у всех»; открыть пост канала.

## Технические детали

- Новый кадр зеркала `ev k=env` с запечатанной нагрузкой `{s,c,m,t}`
  (отправитель, чат, идентификатор письма, конверт); потолок открытого
  текста 48 КиБ — больше в кадр воркера (512 КиБ) не влезает.
- Белый список `MirrorEnvelopes.isSafe()`: реакции, `APUDEL1`, просмотры
  постов, сердечки, прочтения, ссылки на гифки. Разбор этих конвертов на
  втором устройстве — чистая запись в базу, без сети и без байтов.
- Оба пути приёма (основной и запасной через облачный релей) отдают такие
  конверты партнёру; теневое устройство применяет их теми же репозиториями
  (`applyMirrorEnvelope`), личный чат находит по отправителю — идентификаторы
  чатов на устройствах разные.
- Ответные отправки с тени подавлены: движка у неё нет, подтверждения и
  рассылки делает активное устройство.
- Схема базы не менялась; миграций нет.
