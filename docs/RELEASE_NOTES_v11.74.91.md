# APU v11.74.91 — проверки версии через воркер в десятки раз реже

## Что изменилось (раунд 195)

Владелец: «Продолжай следующий пункт» (шаг 4 плана разгрузки из
AI_HANDOFF 0y: снизить расход MQTT/воркера аудитом).

### Разбор расхода

- WSS-мост: запросом считается ПОДКЛЮЧЕНИЕ (переподключения уже
  сдержаны сериями ошибок и фейловером tcp<->wss), сообщения внутри
  соединения запросами не являются -> глубже в ядро лезть не нужно,
  риск не оправдан.
- Главный сгоратель HTTP: checkViaRelay (/update/latest) при КАЖДОМ
  открытии MainActivity (onCreate + resume раз в 5 мин в сессии); на
  «белых» сетях GitHub недоступен -> каждый чек бьёт в наш воркер.
  Плюс «стадо» на сбросе лимита (полночь UTC).

### Фикс: relayIfDue (UpdateChecker)

- checkForUpdate(currentVersion, manual = false): checkGitHub (не наш
  лимит, не тронут) ?: relayIfDue.
- Авто-путь: не чаще RELAY_CHECK_MIN_MS=12ч + личный джиттер
  0..6ч (KEY_RELAY_CHECK_JITTER, один раз на установку) - размазывает
  проверки по суткам. Метка KEY_RELAY_CHECK_AT ставится ДО запроса -
  недоступный воркер не долбится (одна попытка за окно).
- Ручные точки - manual = true, без ограничений: SettingsViewModel
  (кнопка «Проверить новую версию»), UpdateViewModel (экран обновлений).
- О новых версиях рой сообщает сам (авто-upask р193) - сайт остаётся
  ускорителем.

НЕ тронуто: ядро, E2E, апдейт-рой (apkseed/upk/uppwant), downloadApk
(только по нажатию). Дифф 3 файла, +44/-4.
