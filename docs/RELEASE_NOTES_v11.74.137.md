# APU v11.74.137 — диагностика синхронизации и защита доставки

## Что изменилось (раунд 240)

### 1. В Настройках появилась «Диагностика синхронизации»

Настройки → (раздел сети) → **«Диагностика синхронизации»**. Показывает четыре
строки, по которым сразу видно, почему сообщения не едут:

```
роль: ведущий (сеть веду я)  |  зеркало (сети у меня нет)
партнёр: <метка>, N с назад, движок у него: да/нет   |  не видно
канал зеркала: подключён  |  нет связи
недоотправленных сообщений: N
```

Кнопка «Скопировать» кладёт текст в буфер — его можно отправить мне, и я сразу
скажу, где заминка. Это же текст стоит посмотреть при любой жалобе «сообщения не
доходят».

### 2. «Печатает…» больше не занимает очередь сообщений

Сигнал «печатает…» уходит **прямым каналом** (без хранения и повторов). В
обычную (надёжную) очередь попадают только **первый пакет сессии** и «перестал» —
чтобы индикатор появлялся даже там, где прямой канал не работает. Поток
обновлений (раз в 2.5 с, пока человек печатает) надёжную очередь не забивает:
она нужна настоящим сообщениям.

Раньше каждое обновление «печатает…» шло обычной отправкой — это и могло
мешать доставке: очередь наполнялась мимолётными сигналами, которые всё равно
не нужны спустя минуту.

### 3. Уборка мусора и защита от уведомлений (из v11.74.136)

При запуске приложение само удаляет из переписок строки `APUTYP1|…`, накопленные
версиями 132–135, чинит превью списка чатов и счётчик непрочитанных. Пакеты от
собственного узла («уведомление от меня же») больше не показываются входящими.

## Владельцу: что сделать по шагам

1. **Обновить ОБА телефона** до v11.74.137 (важно: на 132–135 строки
   `APUTYP1` всё ещё сохраняются как сообщения — это лечит новая версия).
2. Открыть приложение — мусор уйдёт сам.
3. Проверить свою переписку: если собеседник — **ваш же узел**, сообщений
   «между абонентами» там быть не может. Сравните: в карточке контакта узел
   начинается с `pk_b6866424…`? Если он совпадает с узлом вашего профиля, это
   вы сами (в профиле есть «Мой QR» — его легко отсканировать самому).
4. Если сообщения не ходят с настоящим собеседником — открыть
   «Диагностика синхронизации» на **обоих** телефонах и прислать текст
   (кнопка «Скопировать»). По нему видно: роль устройства, виден ли партнёр,
   есть ли канал и сколько строк ждёт отправки.

## Технические детали

- `MirrorChannel.debugState()` и `MirrorHub.debugStatus()` — человекочитаемое
  состояние (роль, партнёр и его движок, канал, метка устройства);
  `MirrorHub.setPendingOutgoing` обновляет сервис раз в 30 с
  (`MessageDao.countPendingOutgoing`).
- Экран: `SettingsScreen` → строка + диалог с копированием (как у «Сеть
  сообщений»).
- `TypingRouter.publishLocal(..., queueFallback)` — по умолчанию только прямой
  канал; `queueFallback = true` для первого пакета сессии и для «перестал».
- Схема базы не менялась (добавлены только запросы).
