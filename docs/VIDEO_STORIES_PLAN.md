# Видеоистории — реализация и проверка

## Согласованный объём

Видео 1–60 секунд: камера и галерея, передняя/задняя камера до записи,
звук, пауза/продолжение записи, предпросмотр, обрезка, отключение звука,
подпись до 200 символов, обложка. Срок истории — 24 часа.

## Подключено в коде

- Создание истории → «Видеоистория · до 60 с» → галерея или камера →
  редактор → подготовка → отдельное подтверждение публикации.
- CameraX 1.4.2: разрешения на камеру/микрофон, запись без микрофона,
  ограничение длительности, отмена при уходе камеры в фон.
- Media3 1.5.1: предпросмотр выбранного фрагмента; H.264/AAC экспорт,
  удаление звуковой дорожки при mute, обложка из экспортированного фрагмента,
  проверка длительности/размера/SHA-256. Предел готового файла — 24 MiB.
- Потоковый импорт до 256 MiB, приватные временные файлы. Отмена импорта,
  записи и экспорта удаляет файлы, не переданные следующему владельцу.
- `StoryStore`: небольшой видеодескриптор в протоколе и офлайн-снимке,
  обложка обычным фотопротоколом. MP4 не попадает в JSON, Base64 или Bundle.
  Существующий ID нельзя перезаписать историей другого автора.
- `StoryVideoStorage`: проверенные MP4 в noBackupFilesDir, запись через
  временный файл, общий лимит библиотеки 256 MiB, уборка по активной ленте.
- `StoryVideoDelivery`: сохранённый снимок аудитории (до 256 контактов).
  Получатель подтверждает поддержку `video-ready`; старым клиентам идут
  только обложка и пояснение об обновлении, не вложение в личный чат.
- Передача через существующий файловый протокол: отдельное шифрование
  каждому получателю, закреплённые ключи обмена, восстановление по Room,
  подтверждение и повторная передача недостающих частей. Не используется
  групповая принадлежность и не увеличен лимит StoryPhotoParts.
- Не более четырёх незавершённых исходящих копий, одна новая подготовка за
  проход насоса. Завершённые копии освобождают ciphertext, запись остаётся
  для дедупликации. Офлайн-адресаты могут задерживать дальнейшую рассылку.
- Приём предложения требует активную историю от транспортного отправителя,
  совпадение ID/размера/SHA-256 и срока. После сборки проверяются фактические
  метаданные MP4; завершение не создаёт карточку в чате и не зеркалит вложение.
- Файловый насос восстанавливает установку завершённого файла после сбоя,
  убирает просроченные/отозванные передачи. Повторная проверка истории после
  копирования закрывает гонку с отзывом. Отзыв сразу удаляет локальный MP4.
- Проигрыватель ждёт проверенный файл, показывает ожидание/ошибку, имеет
  повтор декодирования, останавливается при удержании, паузе, комментариях
  и фоне. Переход по окончании видео, не по таймеру текста; release при уходе.

## Форма фото и видео

Ровно два варианта: **Круг** и **Обычный**, без отдельного квадратного режима.
Круг — центральное кадрирование при показе; обычный формат сохраняет пропорции.
Видео: выбор до камеры/галереи и в редакторе, предпросмотр камеры с той же маской.
`videoCircle` передаётся в истории, сохраняется офлайн и применяется проигрывателем;
обложка получает ту же форму. Отсутствующее поле у старой истории означает обычный формат.
Фотографии сохраняют существующий `photoCircle`, подпись кнопки уточнена до «Обычный».
Исходник не обрезается маской: в редакторе можно вернуться к обычному формату.
Экспорт теперь масштабирует с сохранением пропорций, без вшитых чёрных полей.
Для круглого видео используется TextureView с Compose- и Android-маской;
камера использует совместимый TextureView-режим. Проверка на устройствах ещё нужна.

## Проверки

- `StoryVideoDraftTest`: границы обрезки, обложка, подпись, mute, соответствие экспорта.
- `StoryVideoWireTest`: привязка к автору/ID/хешу/размеру, граница срока,
  запрет путей в имени, невозможность разрешить видео фотоисторией,
  сохранение видеодескриптора при повторном пакете подписи.
- CI компилирует Android и запускает эти тесты, а также регрессии получателя
  и отправителя файлов. FakeFileTransferDao обновлён под новый запрос Room.
- Статические проверки исходников и существующие проверки редактора/диагностики
  проходят локально. Они **не подтверждают компиляцию или работу на телефонах**.

## Что ещё необходимо подтвердить до публичного релиза

- Успешная сборка актуального коммита и JVM-тесты в GitHub Actions.
  В песочнице нет Java/Android SDK для локальной сборки.
- Два телефона: публикация, capability ACK, передача, проигрывание,
  получатель офлайн, разрыв сети, повторный запуск обоих приложений.
- Удаление во время передачи/копирования и истечение 24 часов:
  отсутствие повторного появления истории и очистка всех копий.
- Реальные разрешения, нехватка места, пауза/фон, большой шрифт, поворот.
- Кодеки/ориентации/HDR: SDR fallback для HDR пока не реализован явно;
  неподдерживаемый исходник должен показать ошибку, не ложную публикацию.
- Много адресатов, дисковые квоты, старый клиент с обложкой без карточки MP4.

Это реализация согласованного базового сценария, не заявление о полном
паритете с Telegram. Новый публичный релиз этим изменением не опубликован.
