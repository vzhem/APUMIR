# Открытие личного чата без ожидания сети

## Найденная задержка

`ChatDetailViewModel.loadMessages()` ожидал `readReceipts.reportRead()` внутри
Room-collector **до** публикации сообщений и сброса `isLoading`. Сама отправка
исполнялась на IO, поэтому индикатор мог продолжать крутиться, но лента ждала
завершения сетевого вызова. При медленном прямом пути/резервах это занимает
секунды. Второй отчёт отдельно отправлялся при стартовом `markAsRead()`.
Это установленная зависимость в коде, не измерение времени на телефоне владельца.

## Исправление

- `ChatHistoryObserver` сначала публикует локальный снимок. Он не вызывает
  сетевые операции внутри подписки на историю.
- Один отдельный worker обслуживает отчёты «прочитано». `StateFlow` хранит
  только последний входящий ID: обновления статуса/закрепа не создают отчёт,
  новые входящие при занятом worker схлопываются до последнего.
- При открытии счётчик непрочитанного снимается локально, без второй отправки.
  Новое входящее по-прежнему вызывает отчёт; ошибки сети не завершают Room-поток.
- Подготовка domain-моделей истории/закрепов работает на Default, а не на UI.
- Определение чата с собственным адресом использует локальные данные. Шапка
  обновляет этот признак независимо от истории; второй DB/JNI-запрос не нужен.
  При маппинге Room сохранён `recipientId`, необходимый этому определению.
- Ошибка локального чтения завершает индикатор. Появляется «Повторить» в общей
  bubble-палитре. Уже показанные сообщения при сбое/повторном чтении не скрываются.
- Отмена экранного scope не трактуется как ошибка чтения/отправки.

IME resize, размещение закрепов отдельно от ленты, права вложений, протоколы
сообщений/файлов и автоматическая помощь участников не менялись.

## Регрессии

`ChatHistoryObserverTest` исполняет реальные Kotlin-coroutine сценарии:
заблокированная отправка и новые снимки; пустой/только исходящий чат; ошибка
отправки; 100 обновлений во время ожидания с одним отложенным отчётом;
обновление закрепа/статуса; ошибка БД и повтор; отсутствие второго worker при
повторе; отмена при закрытии экрана. Запуск: `bash scripts/ci/check-chat-history.sh`
(те же Kotlin/coroutines/JUnit версии, что у приложения; Java 17+; SDK не нужен).

`python3 scripts/ci/check-chat-startup.py` проверяет проводку ViewModel/UI и
ограничения по исходникам. Она не заменяет Kotlin-тесты, сборку APK или физический
phone-тест. Обе проверки блокируют PR CI через существующий core-check script.

На физическом телефоне нужно проверить открытие истории при недоступном соседе,
быстрый переход между чатами, новые входящие во время медленной отправки отчёта,
клавиатуру и закрепы. Из песочницы эти phone-проверки не выполняются.
