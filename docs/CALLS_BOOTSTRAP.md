# Звонки между абонентами — инструкция для нового ИИ-чата

**Единственная задача чата: сделать голосовые звонки между абонентами
в мессенджере APU.** Этот файл — точка входа: что за проект, как здесь
работают и с какого места начинать смотреть звонки. Правила картотеки:
одна тема — один документ; факты о звонках дальше живут только здесь
(и в журнале `AI_COLLABORATION_NOTES.md`).

Свежесть: 2026-09-01, релиз **v11.29.0** в latest.

---

## 1. Что за проект (коротко)

**APU** (`com.vladimir.messenger`, репо GitHub `vzhem/APUMIR`) — Android-
мессенджер с Rust-ядром:

- Android-приложение: Kotlin + Jetpack Compose, Room (схема v12), Hilt.
  Путь: `android-app/app/src/main/java/com/vladimir/messenger/`.
- Rust-ядро: `rust-core/` (libp2p), собирается в `libp2p_core.so`,
  Kotlin-биндинги uniffi: `android-app/app/src/main/java/uniffi/p2p_core/`.
  Rust собирает ТОЛЬКО ПК владельца: `build-rust.ps1` (Windows).
- **Своих серверов хранения нет**: каждый телефон — сервер; внешний ресурс
  допустим только как временный «провод» для уже зашифрованных байтов
  (MQTT-брокеры как relay, публичные «провода» — по согласованию с владельцем).
- Стиль владельца: всё по-русски, «как в Telegram», фирменный стиль
  (темы день/ночь, обои, золотые акценты, термин «@никнейм»).

Главный конвейер владельца: правка → гейт на его Windows-ПК → debug-сборка
на тестовый телефон → приёмка владельцем → релиз тегом.

## 3. Как работать (проверенный конвейер)

- **Ориентир — `main`.** Сессия работает в своей ветке `arena/<id>-apumir`,
  но после каждого коммита пушит и её, и `main`
  (`git push origin <ветка>; git push origin <ветка>:main`), чтобы клон
  владельца `C:\APU-M8` всегда видел свежее через `git reset --hard origin/main`.
- **В песочнице НЕТ компиляторов** (ни JDK/Gradle, ни cargo). Есть только
  лексер `tools/sandbox/struct_check.py` (скобки/кавычки/импорты). Поэтому
  КАЖДАЯ правка кода проходит круг: правка → коммит/пуш → команды владельцу
  (см. ниже) → он шлёт вывод гейта → чиним, если упало. Закладывай 1–2 круга
  на новые API Compose/Rust.
- Команды владельцу давай **копируй-вставь блоками**, PowerShell 5.1:
  никогда `&&`, разделитель `;`, каждый блок начинается с `cd C:\APU-M8;`,
  переменные как `$env:LOCALAPPDATA`. Три шага:
  1. `cd C:\APU-M8; git fetch origin; git reset --hard origin/main`
  2. `cd C:\APU-M8; powershell -NoProfile -ExecutionPolicy Bypass -File scripts\groups-build-gate.ps1 -ExpectedCommit <полный-sha> -Clean`
     (юнит-тесты 160, компиляция, APK, androidTest; GREEN = можно ставить)
  3. `cd C:\APU-M8; powershell -NoProfile -ExecutionPolicy Bypass -File scripts\install-debug-on-phones.ps1 -Serials AUYF6R5923006121`
     (тестовый телефон сейчас ОДИН — Аня; Женин телефон не подключён,
     Стас исключён из тестов; proof = `lastUpdateTime` в выводе)
- **Релиз** — только после GREEN на точном коммите и «выпускай» от владельца:
  аннотированный тег `v11.N.0` на гейтованный коммит → пуш тега → CI сам
  соберёт и создаст prerelease → продвижение в latest: `gh release edit
  --draft`, затем `--draft=false --prerelease=false`; **тумблер срабатывает
  со второго прогона** — проверено на v11.28.0 и v11.29.0, просто повтори.
- Каждую мысль владельца — в `docs/MASTER_PLAN_v2.md`; каждый раунд — строкой
  в `docs/AI_COLLABORATION_NOTES.md`. Одна тема — один документ.
- Ответы владельцу короткие: что сделано + блоки команд.

## 4. Где смотреть звонки (стартовая карта)

Звонков в приложении **нет вообще** — ни UI, ни транспорта, ни аудио
(совпадения «CALL» в `uniffi/p2p_core/p2p_core.kt` — это статусы uniffi,
не звонки). Начинать с этих мест:

1. **Транспорт 1:1.** Как ходят личные сообщения и файлы между двумя нодами:
   `data/relay/`, `data/file/` (пример готового wire-протокола поверх ядра:
   оффер/чанки/квитанции), `data/group/GroupWire*` (пример конвертов
   сообщений), `service/` (фоновая доставка). Звонок = новый wire-тип
   (offer/accept/reject/bye + медиа-поток) по тем же рельсам.
2. **Rust-ядро.** `rust-core/src/` — что уже умеет libp2p-узел: темы,
   прямые соединения, relay, LAN-канал (`LanDirectChannel*` в
   `data/file/` — готовый пример прямого канала поверх ядра, пригодится
   для голоса в локальной сети). Новые FFI-методы ядра = правка Rust +
   регенерация биндингов — это делает ПК владельца (`build-rust.ps1`),
   согласовывай минимальную FFI-поверхность.
3. **UI.** Экран чата `ui/screens/chat/ChatDetailScreen.kt` (там уже есть
   иконка видеокамеры в значках тем — место для кнопки звонка), навигация,
   `ui/components/` (образцы: `AnimatedTopicIcon.kt`, `ChatWallpaper.kt`),
   уведомления/рингтон — по образцу существующих уведомлений сообщений.
4. **Аудио.** В приложении ничего нет: потребуются `AudioRecord`/
   `AudioTrack` (режим `VOICE_COMMUNICATION`), разрешение `RECORD_AUDIO`,
   foreground-service для идущего звонка, обработка прерываний
   (`AudioManager`/`TelecomManager`), echo cancellation (`AcousticEchoCanceler`).

## 5. Подход к задаче (план-минимум для приёмки)

1. Кнопка «звонок» в личном чате → экран звонка (исходящий/входящий,
   принять/отклонить/завершить, таймер, статусы «гудки/соединение»).
2. Сигнализация offer/accept/reject/bye доставляется существующей
   relay-доставкой (офлайн-устойчиво не нужно — звонок живой).
3. Голос: сначала **LAN-прямой канал** (оба в одной сети) и/или прямой
   libp2p-поток; fallback — relay через брокер маленькими чанками
   (помнить грабли: брокер терял фрагменты >33 КБ, кадры голоса мелкие).
   WebRTC со внешним STUN — только после явного «да» владельца
   (внешний ресурс = «провод», но решает он).
4. Приёмка владельцем на двух телефонах (Аня + подключит второй):
   дозвон, голос в обе стороны, завершение, обрыв связи.
5. Гейт GREEN → установка → «выпускай» → релиз по разделу 3.

## 6. Грабли (из журнала, не наступать)

- Compose DrawScope: `drawOval`/`drawRect` = Offset+Size; у `drawArc` нет
  двух-Offset-версии; `Path.moveTo/lineTo` — float-пары; хелперам рисования
  делай Color- и Brush-перегрузки сразу.
- Sandbox пересоздаёт историю git посреди сессии: перед коммитом сверяй
  `git rev-parse HEAD` с `origin/<ветка>`; восстановление — diff/reset/apply.
- PS 5.1 владельца: без `&&`; длинные выводы гейта — норма, смотри
  `RESULT:` в хвосте.
- `versionName` берётся из git-тега; debug показывает `v11.N.0-debug`.
