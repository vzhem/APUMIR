# Копия на флешке: как продолжить работу на новом ПК

Скрипты: `scripts/backup-to-usb.ps1` (сделать копию) и
`scripts/restore-from-usb.ps1` (развернуть её на новом ПК).

Главная идея: **git несёт почти всё, но не всё.** Поэтому копия — это не просто
папка с проектом, а три части: полная история git, файлы, которые git
игнорирует, и инструкция, что доустановить.

---

## 1. Сделать копию

```
powershell -NoProfile -ExecutionPolicy Bypass -File C:\APU-M8\scripts\backup-to-usb.ps1
```

Без аргументов скрипт находит флешку **по метке `APU_BACKUP`**, так что буква
может быть любой. Если метки нет или хочется указать явно — `-Drive E:`.
Добавь `-IncludeToolchainCaches`, если хочешь, чтобы
новый ПК собирал проект и прошивал телефоны **без интернета**: тогда в копию
лягут дистрибутив Gradle 9.5.0 и `platform-tools` (сотни мегабайт).

Скрипт кладёт в `E:\APUMIR-backup-<дата-время>\`:

| Что | Зачем |
|---|---|
| `repo\apumir-mirror.git` | полная история: **все** ветки, **все** теги, remote-ссылки. Восстанавливается обычным `git clone`. |
| `repo\apumir-all.bundle` | та же история одним файлом (~20 МБ) — на случай, если зеркало побьётся. |
| `repo-state.txt` | HEAD, ветка, число коммитов и тегов, было ли дерево чистым. |
| `uncommitted-changes.patch` + `untracked\` | только если были незакоммиченные правки. Из git они не достаются никак. |
| `machine-local\local.properties` | `sdk.dir` — его git игнорирует. |
| `machine-local\.env`, `.dev.vars` | если они есть. |
| `apks\*.apk` | собранные APK — тоже вне git. |
| `MANIFEST.txt` | sha256 и размер каждого файла. |
| `RESTORE-ON-NEW-PC.md` | этот документ. |

### Что важно знать про keystore

`android-app/app/p2p-release.jks` **уже лежит в git** (в `.gitignore` есть
`*.jks`, но файл был добавлен до этого правила, и игнор его не отменяет). Так
что он едет вместе с историей и отдельной защиты не требует. Но именно он
решает, примет ли телефон обновление: подпишешь релиз другим ключом — и каждое
установленное приложение придётся удалять и ставить заново. Скрипт
восстановления проверяет его наличие явно.

**Флешка после бэкапа содержит ключ подписи релиза.** Потерять её не страшно
(ключ есть на GitHub), а вот дать ей уйти не туда — страшно.

### Почему два формата истории

`git bundle verify` печатает «The bundle records a complete history» даже для
бандла, собранного из **поверхностного** (`--depth`) клона, — и такой бандл
потом падает на клонировании с `Failed to traverse parents of commit …`. На
этом мы и поймали проверку: скрипт бэкапа

1. отказывается работать на поверхностном клоне (`git rev-parse
   --is-shallow-repository`), и
2. **реально клонирует** получившийся бандл во временную папку и сверяет HEAD,
   число тегов и наличие keystore.

То есть «проверено» здесь значит «клонировалось», а не «git сказал, что всё
хорошо».

## 2. Развернуть на новом ПК

Вставь флешку (пусть это `E:`). Скрипт восстановления лежит **в корне копии** —
бэкап кладёт его туда именно для этого случая: на новом ПК репозитория ещё нет,
и взять скрипт больше неоткуда.

```
powershell -NoProfile -ExecutionPolicy Bypass -File E:\APUMIR-backup-<дата-время>\restore-from-usb.ps1 -BackupDir E:\APUMIR-backup-<дата-время>
```

То есть `-File` и `-BackupDir` указывают на одну и ту же папку: первая часть —
где взять скрипт, вторая — что разворачивать.

По умолчанию проект встанет в `C:\APU-M8`; другое место — через `-Target`.
Добавь `-RestoreToolchain`, если бэкап делался с `-IncludeToolchainCaches`.

Что делает скрипт сверх обычного `git clone`:

1. **Сверяет каждый файл с `MANIFEST.txt` по sha256.** Недокопированная флешка
   падает сразу, а не через час сборки.
2. Клонирует из зеркала — со всеми ветками и тегами.
3. **Перенаправляет `origin` на GitHub.** Если этого не сделать, `origin`
   останется флешкой, и первый же `git push` запишет обратно на неё.
4. Создаёт локальные ветки: у клона зеркала может не быть рабочей копии вовсе,
   если HEAD зеркала указывает на отсутствующую ссылку.
5. Возвращает `android-app\local.properties` — и предупреждает, что `sdk.dir`
   в нём указывает на **старый** ПК и его почти наверняка надо переписать.
6. Проверяет на месте keystore, обе `libp2p_core.so`, gradle wrapper, скрипт
   гейта и `docs\AI_COLLABORATION_NOTES.md`.

## 3. Чего на флешке нет и что надо доустановить

Копия **не** содержит тулчейн и учётные данные — их на флешку класть нельзя.

1. **JDK 17.** Проект собирается под Java 17
   (`sourceCompatibility = JavaVersion.VERSION_17`).
2. **Android SDK**: платформа **35**, build-tools, platform-tools. `minSdk` = 26.
   Gradle — 9.5.0, AGP 8.7.3, Kotlin 2.0.21; их заберёт gradle wrapper, если
   есть интернет (или возьми их с флешки через `-IncludeToolchainCaches`).
3. **`sdk.dir`** в `android-app\local.properties` — переписать на путь к SDK
   нового ПК.
4. **GitHub CLI и вход в него**: `gh auth login`. Токены и пароли на флешку не
   кладутся принципиально.
5. **Драйверы adb** для телефонов и включённая отладка по USB.

Rust-тулчейн не нужен: `libp2p_core.so` для `arm64-v8a` и `armeabi-v7a` лежат в
git. Правки в `rust-core` на новом ПК, как и на старом, собрать нельзя.

## 4. Проверка, что новый ПК действительно работает

```
cd C:\APU-M8
git fetch --tags
powershell -NoProfile -ExecutionPolicy Bypass -File C:\APU-M8\scripts\groups-build-gate.ps1 -ExpectedCommit <sha из repo-state.txt>
```

Гейт должен напечатать `tests=157 failures=0` и в строке `35 actionable tasks:
N executed` — **ненулевое** `N`. Если `N = 0` и везде `UP-TO-DATE`, тесты не
запускались, и «GREEN» ничего не доказывает: числа взяты из XML-отчётов
предыдущего прогона. Это не паранойя — ровно так выглядел гейт на коммите,
который отличался от проверенного только файлом документации.

Отдельно: `versionName` в `adb shell dumpsys package com.vladimir.messenger`
берётся из `git describe` по **локальным** тегам, поэтому на новом ПК до
`git fetch --tags` он покажет старую версию. О том, какая сборка стоит на
телефоне, говорит только `built:` у APK против `lastUpdateTime` у пакета.

---

## 5. Обновление копии

Копия — это снимок. После каждого релиза (или перед поездкой) просто запусти
бэкап заново: он создаёт новую папку с новой датой и ничего не перезаписывает,
так что старая копия остаётся как точка отката.
