# APU v11.74.76 — авто-слив офлайн-очереди (доставка без «мигания» связи)

## Причина, найденная по отчёту владельца

«Отправил гифку - у меня появилась, у получателя нет». Механизм р178
клал гифку-ссылку в QUEUED_OFFLINE, но досыл existed только в
peer_discovered ПОСЛЕ lightTouch-проверки: при живой связи пульсы
приходят чаще PEER_DEDUP_MS (30 с), поэтому ВСЕ пульсы «лёгкие» и
retryPendingMessagesForPeer не запускался вообще - очередь висела,
пока связь не мигнёт.

## Что изменилось (раунд 179)

1. MessageDao.getQueuedOfflineMessages(limit) - вся офлайн-очередь.
2. ChatRepository.pumpQueuedOffline(limit=20): перебирает хвост
   очереди, каждому - sendMessage; успех -> SENT. Пустая очередь =
   один индексный SELECT (нагрузка ~0).
3. CoreServerService filePumpJob (цикл 20 с): каждый 3-й цикл (раз в
   минуту) -> chatRepository.pumpQueuedOffline(). Работает для ЛЮБЫХ
   QUEUED_OFFLINE (гифки-ссылки р128 и текст) - надёжность переписки
   выросла в целом. Дубли у получателя исключены дедупликацией по id.
4. FULL SYNC/cooldown не тронуты; E2E не менялось; рой по-прежнему
   доставляет БАЙТЫ гифки (ссылка - через переписку).
