## Dual-stack IPv6 (часть 1)

Подробности правки — `docs/DUAL_STACK_IPV6.md`. Проверять по порядку, каждый
пункт отдельным прогоном, чтобы не спутать причины:

- [ ] **IPv4-only сеть — как раньше (главное).** Роутер с выключенным IPv6 или
      точка доступа только с IPv4: сообщение, приём, файл, звонок. Прямой канал
      должен работать, а не уходить на relay.
- [ ] **IPv6-only сеть.** Точка доступа раздаёт только IPv6 (без NAT64/CLAT):
      сосед в той же сети виден, сообщения идут напрямую. Если приложение в такой
      сети живо только через relay — задача не выполнена.
- [ ] **Смешанная пара.** Один телефон с IPv6, второй без: оба видят друг друга
      (v6-сторона по IPv6, v4-сторона по IPv4 через тот же сокет).
- [ ] **mDNS.** В сети с IPv6 объявление содержит AAAA (`avahi-browse -rt
      _p2p-messenger._udp` на компьютере): раньше публиковался один IPv4.
- [ ] **STUN.** Внешний адрес определяется в сети с IPv6 и в сети без неё; в
      каталоге не появляется адрес вида `::ffff:a.b.c.d`.
- [ ] **QR-пэйринг.** Подсказки в QR содержат `[адрес-v6]:порт` и `адрес-v4:порт`,
      второй телефон подключается сразу, без ожидания обнаружения.
- [ ] **TCP-история (7778).** В сети только-v6 история синхронизируется; раньше
      слушатель был на `0.0.0.0` и в такой сети был недостижим.
- [ ] Регресс-контракт в CI: `check-dual-stack.py` зелёный (IPv4-путь и откат на
      `0.0.0.0` нельзя удалить молча).

## Устойчивость сети (часть 2)

- [ ] **Переключение Wi-Fi → мобильная и обратно** (без ручных действий):
      сообщение, отправленное сразу после переключения, уходит само; в
      «Сети сообщений» состояние возвращается к «на связи», а не висит в
      «подключаемся».
- [ ] **Авиарежим на 30 секунд**, затем выключить: очередь досылается сама,
      дублей в чате нет.
- [ ] **Включение VPN** на ходу: соединения переподключаются, файл,
      отправленный до включения, не «зависает» навсегда.
- [ ] **«Только через relay»**: включить, отправить сообщение и файл в той же
      Wi-Fi — доставка идёт (через брокер), прямой канал не используется;
      выключить — прямой канал возвращается без перезапуска приложения.
- [ ] **«Экономия трафика»**: включить, уйти на мобильную сеть, отправить
      сообщение — уходит через брокер; вернуться на Wi-Fi — прямой канал снова
      работает. Перезапуск приложения настройку сохраняет.
- [ ] **Большой файл через IPv6-туннель** (VPN с MTU 1280): передача не
      рвётся на крупных фрагментах.

## Что пока нельзя утверждать

- Наличие UI-вызовов не равно успешной пользовательской проверке на устройстве.
- Зелёные JVM/CI-тесты не подтверждают реальный NAT, произвольные мобильные сети, расход батареи или полезную ёмкость роя.
- Подписанная квитанция подтверждает конкретный принятый пакет, но не уникальность человека и не честность вклада.
- Content-addressed фотоистории не означают готовую раздачу контента для групп/каналов; она остаётся задачей следующих этапов.
