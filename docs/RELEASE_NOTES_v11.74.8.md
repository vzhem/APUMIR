# APU v11.74.8 — раздел «Сервер» и резервные копии адресов

## Главное: резервные копии азбуки адресов

Самое ценное в приложении после личности — **азбука адресов** (какие адреса
у кого в какой сети). Теперь она автоматически резервируется на нашем
сервере:

- **Шифрование на телефоне**: копия зашифрована AES/GCM ключом, выведенным
  из приватного ключа узла. Сервер хранит непрозрачные байты и прочитать
  копию не может — открыть её может только та же личность.
- **Автоматически**: первая копия через ~3 минуты после старта, дальше
  каждый час — но отправка происходит только если азбука менялась.
- **Само восстановление**: при переустановке приложения (после
  восстановления личности с полки) азбука подтягивается с сервера ДО старта
  движка — адреса сразу готовы.
- **Руками**: Настройки → Сервер → «Резервная копия адресов» → «Создать
  копию» / «Восстановить».

На сервере добавлены эндпоинты `/addrbook/put` и `/addrbook/get`
(полка `addrbook|<node_id>`, до 200 КБ, то же хранилище, что у сундуков
личности). Вступают в силу после деплоя воркера.

## Новое: раздел «Сервер» в настройках

В настройках появился раздел **«Сервер»** — всё о нашем relay-сервере в
одном месте:

- **Адрес сервера** (`p2p-relay.1985vzhem.workers.dev`) и его состояние:
  живой, время отклика (замер `/health`).
- **Сообщения (рой)** — строка переехала сюда из «О приложении»: режим
  роя (наш брокер / запасные / wss-мост), давность ConnAck, последняя
  ошибка.
- **Резервная копия адресов** — состояние копии и кнопки.

## Сервер (воркер)

- `POST /addrbook/put` / `GET /addrbook/get` — резервные копии азбуки
  (требуют деплой воркера; скрипт деплоя тот же `deploy-mqtt-bridge.ps1`,
  при ошибке 10079 сам повторяет деплой без миграций).

## Напоминание

- Деплой воркера (владелец): скрипт ставит и свой MQTT-брокер (v11.74.7),
  и новые /addrbook-эндпоинты. До деплоя рой работает на прямом
  соединении с hivemq — всё как было.
- E2E-шифрование сообщений не менялось.
