# APU — подготовка к первой волне публикации

Черновик, не для подачи. Маршрут: [план развития, §2–5](DEVELOPMENT_PLAN.md).
Владелец подтвердил пилот в Uptodown и отдельную магазинную сборку. После проверки первой карточки и установки
из магазина адаптируем материалы для APKPure, Aptoide, APKMirror и Softpedia.
NashStore — только после проверки актуальности. RuStore относится ко второй волне.

## До первой подачи

- [ ] Сверить актуальные требования Uptodown и доступность кабинета разработчика.
- [ ] Согласовать ключ подписи и минимальную версию Android по §3 плана; проверить
  подпись кандидата и обновление поверх действующей версии без потери данных.
- [ ] Отключение встроенного обновлятора согласовано и внесено. Проверить, что магазинный вариант не предлагает скачать APK и не
  запрашивает разрешение `REQUEST_INSTALL_PACKAGES`, а вариант GitHub/сайта
  по-прежнему обновляется. В общем манифесте разрешение остаётся для прямой сборки.
- [ ] Собрать и выбрать подписанный лёгкий `app-storeRelease.apk`, зафиксировать версию,
  коммит и SHA-256. Не загружать `app-full.apk` или бандл репозитория.
- [ ] Проверить установку, личный и групповой чат, отправку файла и доставку
  уведомления на заблокированном телефоне. Зафиксировать устройства и результат.
- [ ] Подготовить иконку 512×512 и минимум три реальных скриншота без личных
  данных (список чатов, личный чат, группа); сверить лимиты площадки.
- [ ] Подтвердить контакт поддержки, оператора данных, возрастной рейтинг и
  фактическую обработку данных (включая ретрансляторы и push). Подготовить
  политику конфиденциальности и согласовать место публикации; до подачи
  проверить, что согласованная политика доступна по публичному URL.
- [ ] Утвердить тексты и получить отдельное разрешение на подачу конкретной
  сборки в Uptodown. После подачи записать статус модерации и ссылку на карточку.

  именами, аватарами с фото и текстом личной переписки.

- Поддержка: `1985vzhem@gmail.com`.
- [Политика RU/EN](../website/privacy.html): также доступна офлайн из настроек.
  До подачи сверить с оператором данных, фактическим окружением и сроками хранения,
  затем разместить на официальном сайте (предложенный URL: `https://apu.clan.su/privacy.html`; пока не опубликован).

Команда для подготовленного Android/Rust-окружения: из `android-app` выполнить
`./gradlew :app:assembleStoreRelease -Papu.lightBase=true`. Без отдельной
релизной подписи и проверки версии это только кандидат для внутренней проверки.
Не отправлять APK, подписанный старым ключом из репозитория. Для подачи применить
действующую процедуру переподписи с lineage из `build-release.yml`, проверить
сертификат и сравнить с текущим публичным APK, проверить объединённый манифест
на отсутствие `REQUEST_INSTALL_PACKAGES`; исключить понижение versionCode.
Не запускать workflow публикации обычного релиза ради этого APK.

## Передача работы между чатами — без секретов

1. Владелец сам входит или регистрируется в [Uptodown Developers Console](https://developers.uptodown.com/), подтверждает почту и заполняет обязательные данные. На этом этапе приложение не отправляет.
2. Агент готовит APK, контрольную сумму, материалы и проверяет статус CI. Владелец проверяет установку и обновление на телефоне. Иконка для карточки берётся из актуального мастера `design/app-icon/apu-final-icon-mesh.png`.
3. Владелец размещает согласованную политику на официальном сайте или даёт уполномоченному участнику доступ через сам сервис. В документе фиксируется проверенный публичный URL.
4. Когда проверки пройдены, владелец загружает APK и материалы в кабинете и отправляет на модерацию. Если интерфейс непонятен, можно прислать скриншот с закрытыми личными данными. После подачи здесь фиксируются дата, версия, ссылка и статус.

Для следующего ИИ-чата достаточно ссылки на этот файл и ветки. Записываем ссылки, версии, статусы и ответственного — **не** пароли, коды, резервные коды, токены, cookies или ссылки подтверждения из писем. Их нельзя хранить ни в Git, ни в скрытом файле проекта. Данные для входа — только в личном менеджере паролей владельца.
