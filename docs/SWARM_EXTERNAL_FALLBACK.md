# Рой прежде внешней сети — критерии выпуска

**Статус 2026-10-13: цель владельца, НЕ выпущено.** Последняя общая APK —
`v11.74.352`. В исходниках после неё добавлена локальная история проверенных
адресов и срочное распространение **своей** свежей подписанной lease через PEX.
Это не тождественно правилу «внешняя сеть только после отказа роя».

## Желаемое правило

1. При старте и при нехватке сведений пробовать сохранённые адреса, локальный
   mDNS и подписанный обмен APUX1 с доступными соседями. Количество известных
   контактов (хоть 50) само по себе не является доказательством доступности.
2. Только после ограниченного по времени поиска **достижимого** узла и
   безуспешного запроса нужных сведений обращаться к внешнему ресурсу — ровно
   за недостающим, с ограничением времени, трафика и повтора. Как только
   прямой маршрут подтверждён, лишнее внешнее соединение должно закрыться.
3. Новые публичные адреса распространять по рою только как подписанные
   владельцем краткосрочные записи. Чужой брокер/STUN/registry не может
   утверждать доступность третьего телефона: его IP — кандидат до прямого
   аутентифицированного ответа. Не распространять приватные истории IP,
   содержимое сообщений, ключи и неподписанные сведения как «важные факты».
4. В режиме строгой изоляции входящие от старых APK и спящих телефонов могут
   не дойти: владелец отдельно выбрал этот риск. До объявления режима готовым
   нужны управляемый переход между маршрутами, наблюдаемое состояние
   недоставленных сообщений и проверки на реальных устройствах.

## Что пока нарушает правило

| Путь | Сейчас | Что требуется до массового релиза |
|---|---|---|
| MQTT в Rust | Запускается безусловно при старте ядра; внешние брокеры или WSS worker; presence и входящие сообщения/звонки | Отложенная подписка и ограниченная bootstrap-сессия; проверка **ответа** роя, переход обратно, честное состояние доставки при отсутствии подписки |
| STUN | Внешняя проба при запуске, потом примерно раз в минуту для адреса и NAT | Сначала адрес/проверка связи от подписанного соседа; отдельный расчёт поддержания NAT и fallback при смене сети |
| Звонок | `CallBrokerLink` открывает публичный MQTT на исходящем и входящем offer даже при прямой сети | Прямая сигнализация/медиа прежде брокера; ожидание bounded, fallback только когда нужного пути нет; тест сна/переключения сети |
| Зеркало | `MirrorChannel` всегда соединяется с worker по WSS у созданной личности | Прямой канал между устройствами одной личности либо честное исключение из строгого правила |
| Азбука / другие сервисы | Автокопия азбуки пишет в worker при изменении файла; обновления, GIF и др. используют внешние API | Привязать **каждую** автоматическую операцию к отсутствующим данным, результатам роя и явному действию человека; подтверждать получение копии, не полагаться на один `send()` |

## Уже есть в коде

- Прямой QUIC, mDNS, личное presence, подписанные APUX1 leases (до 24 ч),
  запрос нужных контактов, ввод через общего соседа и онлайн-помощники.
- Азбука хранит последний замеченный адрес; отдельная приватная история
  хранит до четырёх **прямо подтверждённых** публичных адресов контакта.
- После смены своего публичного адреса телефон сразу предлагает подписанную
  lease не более чем двум недавно проверенным публичным соседям через PEX,
  используя старые общие лимиты (2 параллельных / 6 в минуту). Они могут
  передать запись дальше, но получатель не объявляет владельца онлайн,
  пока тот лично не ответит. Если соседей нет или лимит исчерпан, обычный
  прямой поиск и старые резервные каналы пока остаются.

## Барьер публикации

Не выпускать APK с обещанием «рой прежде внешней сети», пока не выполнены
все пункты таблицы и не пройдены: блокирующие Rust/Android CI, тесты реальных
двух и более телефонов на одной Wi-Fi, разных мобильных сетях, после смены
адреса и сна экрана; отдельно проверить сценарий старого APK и последствия
выбранного строгого режима для входящих. Без сетевых счётчиков нельзя
подтвердить, что при живом рое в самом деле нет обращений к внешним узлам.
Не менять тег `v11.74.352` и не путать гибернацию worker с этим переходом.
