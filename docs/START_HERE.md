## 1. Суть проекта (одно дыхание)

**APU** (`com.vladimir.messenger`, репо `vzhem/APUMIR`) — Android-мессенджер
с Rust-ядром. Главная цель владельца: **надёжная и максимально быстрая
передача файлов любого практического размера через любые сети БЕЗ своих
серверов хранения**. Серверов хранения нет: каждый телефон — сервер. Внешний
ресурс допустим только как временный провод для уже зашифрованных байтов.
Второй большой пласт — раздел ГРУППЫ/КАНАЛЫ «как в Telegram» и фирменный стиль
(темы день/ночь, обои, золотые акценты, всё по-русски, термин «@никнейм»).

## 4. Первые три шага нового чата (обязательно, до задачи)

1. **Выровнять песочницу.** Локальный HEAD в Arena-песочнице может висеть на
   старом базовом коммите, даже когда все работы давно запушены. Выполни:
   `git fetch origin arena/01a03c3d-apumir` → `git rev-parse FETCH_HEAD` →
   `git reset --hard FETCH_HEAD` (если в рабочем столе нет неприкаянных
   правок; если есть — сначала `git reset -q FETCH_HEAD` и посмотри
   `git status`). Ожидаемый кончик на 2026-08-29 — `39d4557`.
   В песочнице нет тегов по умолчанию: `git fetch --tags origin`.
2. **Прочитать** раздел 2 и в первом ответе владельцу коротко назвать:
   последнюю выпущенную версию, кончик ветки, что доказано на телефонах,
   что НЕ доказано.
3. **НЕ начинать код по своему почину.** Владелец сам даст серьёзную задачу.
   До неё — только чтение и короткий честный доклад.

## 5. Правила владельца (нарушать нельзя)

- Один маленький шаг: правка → проверка → следующий шаг. Проект не
  перезапускать, не переписывать «с нуля».
- По-русски и простыми словами; объяснять, какие этапы «молчат» и как
  проверить живость.
- **Телефоны не трогать** без явного предупреждения и поимённо
  (Стас `11567254BK001192`, Аня `AUYF6R5923006121`, Женя `3B665800EES00000`).
  Команды на телефоне выполняет сам владелец.
- Команды для Windows — только одной строкой и только так:
  `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\<имя>.ps1`.
  Многострочные блоки в консоль НЕ вставлять (были парс-краши). **Команду с
  опечаткой не давать даже с исправлением в том же сообщении.** Команды
  дублировать полностью, по одной строке.
- git без пайплайнов и без `2>$null`; перед КАЖДЫМ коммитом `git log --oneline -1`;
  при рассинхроне fetch + reset. Коммиты/пуш своей arena-ветки — без спроса;
  **релиз/тег — только с явного разрешения**.
- `.github/workflows/*` не пушить и не менять.
- Юнит-тесты не смешивать с assemble в одном `--tests`; «зелёный фильтр» ≠ гейт.
- Грубый brace-чекер врёт — есть лексер `tools/sandbox/struct_check.py`
  (полная версия; короткие ранние копии лежат в `tools/` и не являются
  эталоном).
- Свежесть сборки на телефоне смотреть по `dumpsys lastUpdateTime`;
  установка только `adb install -r -t -d`.
- Непроверенное на экране называть непроверенным. Имя приложения — «APU».
- **После каждого большого обновления** предлагать владельцу: «вставьте белую
  флешку (APU_BACKUP)» и одну команду из раздела 3.

## 6. Грабли, на которые уже наступили (не повторять)

- **Песочница отстаёт от origin** (2026-08-29: локальный HEAD висел на
  `f0ca016`, пока origin был на `39d4557`, а весь код раундов 20–46 лежал в
  рабочем столе неотреслеженным). Сначала fetch/reset, потом выводы.
- `AI_HANDOFF.md`/`NEXT_AI_CHAT_BOOTSTRAP.md` могут быть старше реальности —
  сверять с фактическим checkout и `/releases/latest`.
- PowerShell 5.1: `$ErrorActionPreference='Stop'` + stderr от `gh`
  («release not found», пока Actions строит) убивает скрипт. В циклах ожидания
  вызывать gh через `cmd /c "gh ... 2>nul"`.
- `gh` определяет репозиторий по текущей папке: в скриптах
  `Push-Location 'C:\APU-M8'`, в разовых командах владельца `-R vzhem/APUMIR`.
- Сеть на ПК владельца нестабильна: promote может оборваться на середине.
  Тогда добить вручную:
  `gh release edit <tag> -R vzhem/APUMIR --draft=true` и следом `--draft=false`.
- Снять prerelease НЕДОСТАТОЧНО: `/releases/latest` двигается только через
  цикл draft → publish.
- Длинные команды с путями при копировании владельцем искажаются — такие вещи
  заворачивать в `.ps1`, а не давать строкой.
- Не давать команды копирования на диск вслепую: сначала `Get-Volume`,
  потом путь с реальной буквой (скрипт ищет флешку по метке).
- Compose foundation 1.7.6: `combinedClickable` — `@ExperimentalFoundationApi`
  (`@OptIn` + импорт); `clip` требует `import androidx.compose.ui.draw.clip`;
  `LineLimits` НЕ существует; приём контента с клавиатуры работает только в
  `BasicTextField(state = TextFieldState)` + `Modifier.contentReceiver`.
- `MessengerColors.of(...)` / `colors.gold` / `ic_launcher_foreground` — таких
  сущностей нет, не выдумывать.
- Гейт `scripts/groups-build-gate.ps1` при провале удаляет APK; после правок,
  задевших kapt/Room, запускать с `-Clean`.
- Release-APK подписан другим ключом — поверх debug не ставится.

## 7. Как устроен выпуск релиза (проверено на v11.23.0)

1. `scripts/make-release.ps1 -Version vX.Y.Z -ExpectedCommit <sha>` —
   проверяет чистоту дерева, гоняет гейт, ставит тег и пушит.
2. GitHub Actions (`.github/workflows/build-release.yml`) собирает подписанный
   `app-release.apk` (~12–20 мин) и публикует **PRERELEASE** с body-заглушкой.
3. `scripts/promote-release.ps1 -Version vX.Y.Z` — ждёт релиз с APK, снимает
   prerelease, делает draft → publish, сверяет `/releases/latest`.
4. `gh release edit vX.Y.Z -R vzhem/APUMIR --notes-file docs\RELEASE_NOTES_<версия>.md`
   — краткие заметки (их видит окно обновления в приложении).
