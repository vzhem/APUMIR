# APU v11.74.113 — финальная семантика «Я сервер»: тяжёлое/лёгкое

## Что изменилось (раунды 216–217)

Владелец уточнял семантику переключателя трижды, финальная формулировка:
«Всё тяжёлое абонент на себя не берёт. Сервер берёт на себя всё. Всё,
что нужно для стабильной связи — и текстовые сообщения, и резервные
копии профилей — этим занимаются все. Тяжёлые файлы (картинки, видео,
гифки) абонент не пересылает. Маленькие документы, например которые
нужны для стабильной связи, пересылаются тоже обычным абонентом».

## Итоговое поведение

**СЕРВЕР** («Я сервер» = включено, дефолт):
- принимает НОВОЕ чужое на хранение (для контактов не в сети);
- раздаёт всё, что есть: и тяжёлое, и лёгкое.

**АБОНЕНТ** («Я сервер» = выключено):
- НОВОЕ чужое на хранение не принимает (гейт р215 в CustodyPolicy);
- тяжёлое не пересылает: файлы сообществ отдаёт только если они
  ≤ 2 МБ (ServerMode.LIGHT_SERVE_MAX_BYTES) — маленькие документы и
  стикеры проходят, картинки/видео/гифки/большие файлы — нет
  (гейт в GroupFileSwarm.sharedSource, р217);
- APK обновлений и патчи раздаёт ВСЕГДА (гейт р215 снят в р216 —
  это его скачанный файл и он нужен всем телефонам);
- текстовые сообщения и резервные копии (APUBK1, свой протокол) —
  своими путями, гейтов не имеют: несут все (проверено по коду).

Черта «лёгкого» — 2 МБ (константа, легко поменять).

## Механика

- `ServerMode` (prefs `im_the_server`, дефолт ВКЛ) + константа
  LIGHT_SERVE_MAX_BYTES.
- Гейты: FileTransferRouter.CustodyPolicy.acceptsFrom (не принимать
  чужое); GroupFileSwarm.sharedSource (лёгкое ≤ 2 МБ). ApkSeeder —
  без гейтов (р216).
- Решение читается на каждый запрос — действует сразу.

НЕ тронуто: ядро, E2E, wire-протокол, LAN, личные передачи 1:1
(отправка — действие человека, не раздача).
