# Докачиваемые пакеты функций: лёгкая база + раздел в настройках

Решение владельца: приложение полноценное, но первая установка — маленькая
и сразу рабочая. Тяжёлый функционал владелец докачивает переключателями в
настройках (раздел «Дополнительные функции»). **Ограничений по рангам на
докачку нет**: переключатели доступны каждому с первого запуска.

Код-источник истины каталога:
`android-app/app/src/main/java/com/vladimir/messenger/data/featurepacks/FeaturePackCatalog.kt`.
Контракт: `scripts/ci/check-feature-packs.py`, тест: `FeaturePackCatalogTest`.

## Замер: из чего состоят нынешние 233 МБ

Замер выполнен в CI (прогон 41695927881, `scripts/ci/apk-composition.py`,
размеры — как лежат в файле, сжатые):

| Группа | Размер |
|---|---:|
| Файл APK целиком | 222,7 МБ |
| Нативные библиотеки, все 3 ABI | 178,8 МБ |
| — arm64-v8a | 64,1 МБ |
| — armeabi-v7a | 47,4 МБ |
| — x86_64 (эмулятор/лаунчер) | 67,3 МБ |
| Dex (код) | 20,2 МБ |
| Ресурсы (res + arsc) | 16,4 МБ |
| Assets | 6,6 МБ |

Самые тяжёлые библиотеки (все ABI суммарно): перевод ML Kit
(`libxeno_native` 54,8 + `libtranslate_jni` 43,2 + `liblanguage_id_l2c_jni`
2,8) = **100,8 МБ**; ядро сети `libp2p_core` — 29,4 МБ; Vosk — 25,6 МБ;
детектор лиц ML Kit — 22,5 МБ.

## Что остаётся в базе, а что уезжает в пакеты

База обязана работать с первого запуска: сообщения и сетевое ядро
(`libp2p_core` не пакет и не обсуждается), сообщества, приём и просмотр
файлов, игра сердечек, профиль, обновления. Код функций (dex, 20 МБ)
остаётся в базе целиком — качаются только нативные части, а каждый вызов
нативной части обязан проверять наличие пакета и честно предлагать
догрузку вместо падения.

| Пакет | Функция | Библиотеки | arm64 | arm32 | x86_64 |
|---|---|---|---:|---:|---:|
| `translate` | Перевод сообщений на телефоне | xeno, translate_jni, language_id | 37,1 МБ | 27,3 МБ | 36,5 МБ |
| `voice-text` | Голосовые в текст (Vosk) | libvosk | 8,5 МБ | 7,9 МБ | 9,2 МБ |
| `face-effects` | Лицо, фильтры, фон в видео | face_detector_v2_jni | 8,1 МБ | 5,2 МБ | 9,2 МБ |

Итоги:

- **Лёгкая база** после выноса пакетов: 222,7 − 148,9 ≈ **74 МБ** одним
  универсальным файлом (все три ABI, как сейчас — решение от 2026-10-28
  про универсальную раздачу не меняется).
- **Догрузка одного телефона** (только его архитектура): все три пакета
  arm64 — **53,7 МБ**, arm32 — 40,4 МБ, x86_64 — 54,9 МБ. По отдельности
  владелец качает только то, что включил.
- **Файлов догрузки на релизе: 9** (3 пакета × 3 архитектуры,
  `feature-pack-<id>-<abi>.zip`) плюс один манифест `feature-packs.json`
  (версия, размеры, SHA-256 каждого файла). Телефон из этих девяти берёт
  не больше трёх — по одному на пакет.

Языковая модель Vosk и модели перевода ML Kit и сейчас скачиваются
отдельно при первом использовании; в размеры пакетов они не входят.

## Как пакет доезжает и встаёт: рой, а сайт — запасной

Порядок источников — по замыслу владельца «у кого есть, тот и раздаёт»
(механизм уже работает для обновлений APK, `docs/UPDATE_SEEDING.md`):

1. **Сосед по рою, у которого пакет уже скачан.** Телефон спрашивает
   соседей (`fpask`), получает объявления (`fpk`: пакет, архитектура,
   SHA-256, размер), просит пакет (`fpwant`) и принимает zip файловой
   машиной в виртуальное сообщество `packseed`. Принявший телефон сверяет
   SHA-256 с объявлением, кладёт пакет в `filesDir/feature_packs/` и
   **сам становится раздающим**.
2. **Другие соседи.** Отказ соседа (`fpnone`) — просьба уходит
   следующему из объявлений, а не виснет.
3. **Официальный сайт.** Если в рое пакета ни у кого не нашлось
   (пауза 30 с), телефон скачивает zip с `apu.clan.su/downloads/` и
   сверяет SHA-256 по официальному манифесту
   `apu.clan.su/downloads/feature-packs.json` — после чего тоже раздаёт
   пакет рою.

Провода: `GroupWire` виды `fpk`/`fpwant`/`fpnone`/`fpask`, диспетчер —
`GroupRepository`, раздача и приём — `data/featurepacks/FeaturePackSeeder`,
предложения файловой машины маршрутизирует `FileTransferRouter`, помпа —
`CoreServerService`. Целостность: пакет принимается только при совпадении
SHA-256 (объявление соседа или официальный манифест). Ранги в раздаче не
участвуют: раздавать и получать может каждый телефон.

Что осталось по стадиям: сборка релиза вырезает пакетные `.so` из
базового APK и публикует 9 zip + манифест (на GitHub Release и на
`apu.clan.su/downloads/`); нативные вызовы функций проверяют пакет и
предлагают догрузку вместо падения; обновление приложения сверяет
версии пакетов с новым манифестом.

## Стадии

- **Стадия 1 (сделано):** замер состава, каталог пакетов, раздел
  «Дополнительные функции» в настройках с переключателями без рангов,
  сохранение выбора владельца.
- **Стадия 2 (сделано в коде):** раздача пакетов роем по образцу роя APK
  («у кого есть — тот и раздаёт», отказ ведёт к следующему соседу),
  официальный сайт как запасной источник, SHA-256 на каждом шаге,
  статусы пакетов в настройках («спрашиваем соседей», «качается от
  соседа», «скачано — раздаётся соседям»). Пакеты при этом ещё не
  опубликованы: в рое их ни у кого нет, а манифеста на сайте ещё нет,
  поэтому попытка догрузки честно закончится статусом «не удалось
  скачать», пока не выйдет стадия 3.
- **Стадия 3:** сборка публикует пакеты и манифест (GitHub Release +
  `apu.clan.su/downloads/`); вынос пакетных библиотек из базового APK
  (база ≈74 МБ); ограждения нативных вызовов (перевод, Vosk, лицо);
  проверка на телефоне: свежая установка работает без пакетов; включение
  перевода/голоса/эффектов догружает и оживляет функции; обновление
  приложения не теряет установленные пакеты.

## Что осталось проверить на телефоне (стадия 3)

- Свежая установка лёгкой базы: чаты, группы, приём файлов, сердечки.
- Включение каждого пакета в настройках: размер совпал, функция ожила
  без переустановки приложения.
- Отключение/удаление пакета: функция честно предлагает догрузку,
  приложение не падает.
